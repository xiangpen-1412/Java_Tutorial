# Integer Division & Double Keys：除法转换时机与正负零

> 来源：[[14-149 - Max Points on a Line]]、[[09-643-Maximum Average Subarray I]]。

## 1. 返回 double，不代表除法已经使用 double

本次两题都遇到了整数除法丢失小数：149 直接用 `int` 计算斜率；643 在 `sum / k` 计算完成后才转成 `double`。共同需要检查的是除法执行时操作数的类型，不能只看接收结果的变量或返回类型。

```java
double a = 5 / 2;          // 2.0
double b = (double) (5 / 2); // 2.0
double c = (double) 5 / 2; // 2.5
```

前两行的操作数都是整数，因此先执行整数除法，结果 2 再转成 2.0。小数部分已经在除法时丢失，事后转换无法恢复。Java 整数除法向零截断，例如 `-5 / 2 == -2`，不能概括成对所有正负数都向下取整。

第三行先把一个操作数变成 `double`，除法本身才按浮点数运算。除数也可以先转换，例如 `5 / (double) 2`。

应用到这两道题：

```java
double slope = (double) dy / dx; // dx == 0 的竖直线另行处理
double average = (double) sum / k;
```

需要检查的是执行 `/` 那一刻两侧操作数的类型。公式正确、接收结果的变量类型正确，都不能代替这个检查。

## 2. double 的正零和负零，在 HashMap 中会成为不同的 key

浮点数有 `0.0` 和 `-0.0` 两种零。例如：

```java
double positiveZero = 0.0 / 1;  // 0.0
double negativeZero = 0.0 / -7; // -0.0
```

它们的比较取决于使用哪条规则：

```java
0.0 == -0.0                           // true
Double.valueOf(0.0).equals(-0.0)       // false
```

第一行比较基本类型 `double` 的数值。第二行按 `Double` 对象的相等规则比较，会区分正零、负零。[Java Double 官方说明](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html#equals(java.lang.Object))

`HashMap<Double, Integer>` 会自动把 `double` 装箱成 `Double`，结合哈希值与对象相等规则识别 key，所以正零、负零可以分别保存。不能从 `0.0 == -0.0` 推断它们必然属于同一个 Map key；也不能将这个现象误认为一般的浮点舍入误差。

在 149 中，水平线上的点分布在基准点两侧时，分母一正一负，可能得到两种零。最小修正是在写入 Map 前统一表示：

```java
if (slope == 0.0) {
    slope = 0.0;
}
```

判断阶段：正零和负零都会满足 `== 0.0`。赋值阶段：右侧字面量 `0.0` 是正零，原来为负零的变量会被改写。因此这一行有实际作用。

这种归一化适用于“业务含义认为两种零相同”的场景，例如水平线斜率，不应机械套到需要保留浮点符号的所有计算中。

## 3. 数学等价关系要落实到 key 的表示

本次应分清三件事：

- **整数截断**：`1 / 2` 与 `1 / 3` 都得到 0，本来不同的斜率被错误合并。应在除法前转换类型，或改用精确分数表示。
- **正负零分离**：两个水平线方向在数学上相同，却产生不同的 `Double` key。应先统一表示。
- **一般浮点舍入**：浮点数无法精确表示所有分数。若要求精确地按有理数分组，可以用 GCD 约分并统一符号后的整数对表示。

设计哈希 key 时，既要保证应归在一起的对象产生相同表示，也要避免把需要区分的对象合并。149 中的 GCD 推导和方向规范化见对应题目笔记。
