# 北京动态分类写作规范及模板

> 知识库用途：供 OA 公司新闻智能体识别、整理和生成“北京动态”类稿件。  
> 版本：V1.0  
> 归纳依据：用户提供的 5 个“公司信息（公司新闻）”压缩包，共 37 个 DOCX；合并重复后涉及 25 个不同标题，其中 23 篇正文有效。  
> 配套资料：《公司领导标准职务表》《公司部门标准名称表》所在的合并 Excel 文件。

## 1. 类别定义

“北京动态”不是公司自身经营活动新闻，而是对北京市重要政务、经济、科技、产业、民生和应急信息进行选编、转载或摘要发布的栏目。

该类稿件的核心任务是：

1. 准确传递北京市最新政策、会议、调研、产业发展、公共服务和应急信息。
2. 保留原始新闻的政治表述、事实口径、数据口径和来源信息。
3. 让公司内部读者快速了解与首都发展、数字经济、信息通信、人工智能、城市治理等相关的外部动态。
4. 不把外部新闻改写成公司自主新闻，不虚构本公司的参与、贡献或表态。

本类别的固定识别特征是标题以“【北京动态】”开头，正文末尾保留“原文链接”和“编辑”信息。

## 2. 适用范围

根据现有有效样本，建议将“北京动态”分为四种写作子类型。

| 子类型 | 样本归类数量 | 典型内容 | 主要结构 |
|---|---:|---|---|
| 市领导活动与重要会议 | 8 | 调研、检查、会议、党课、警示教育、慰问 | 活动概况—现场/议程—领导要求—参加人员 |
| 应急预警与城市安全 | 5 | 上汛、暴雨预警、防汛检查、应急响应 | 预警事实—影响范围—响应措施—公众/单位要求 |
| 政策规划与标准发布 | 5 | 行动方案、产业规划、地方标准、建设计划 | 发布事实—目标背景—重点任务—实施安排—意义 |
| 产业科技与经济进展 | 5 | 产业数据、创新中心、工作组、科技大会、项目成果 | 核心成果—关键数据—主要内容—应用价值—后续方向 |

上述归类用于选择写作模板，不代表新闻只能属于一个主题。若一篇稿件同时涉及领导调研和产业发展，优先按新闻事件的主导形式分类：有完整领导行程和讲话要求的，按“市领导活动与重要会议”处理。

## 3. 不适用范围

以下内容不应归入“北京动态”：

- 公司内部会议、公司领导调研、公司经营成果、公司项目交付。
- 公司产品宣传、客户案例、员工活动、党建活动等公司自主新闻。
- 只有观点、传闻或网络讨论，缺少权威来源的信息。
- 尚未正式发布的政策、未经确认的数据和内部流转材料。
- 与北京无明确关系，且对公司和首都发展无明显参考价值的一般行业新闻。

## 4. 现有样本的固定版式

现有 OA 稿件普遍采用以下版式：

```text
【北京动态】[标题]
[创建时间，格式：YYYY-MM-DD HH:mm:ss]
供稿人：[姓名]
供稿部门：[部门标准名称]
-----------------------------------------------------------------------
[正文]

原文链接：[完整 URL]
编辑:[编辑姓名或工号]
```

生成时必须遵守以下规则：

- “供稿人”“供稿部门”“编辑”必须由用户或系统字段提供，不得由智能体猜测。
- 供稿部门名称须与部门标准名称表完全一致。
- 创建时间是 OA 发布字段，不等同于新闻事件发生时间。
- 原文链接必须完整、可追溯，不得编造。
- 若来源材料没有编辑字段，输出“编辑：待补充”，不得填入样本中的固定编辑人员。
- 标题中的“【北京动态】”只出现一次。

## 5. 通用写作原则

### 5.1 事实优先

时间、地点、人物、职务、单位、文件名称、会议名称、数据、预警等级、响应等级和原文链接必须与来源一致。

不得把：

- “拟发布”改成“已发布”；
- “将建设”改成“已建成”；
- “计划开展”改成“已经完成”；
- “参与编制”改成“主导编制”；
- “提出目标”改成“已经实现”；
- “超过、约、近、余”改成精确数字。

### 5.2 来源忠实

“北京动态”以外部信息为主，原则上应保留来源材料的新闻事实和逻辑顺序。允许压缩冗余、调整段落和增加小标题，但不得改变原意。

来源材料含“据北京日报消息”“记者从……获悉”“本报讯”等来源说明时，应根据转载规范保留。不得把来源媒体的采访成果写成公司自行采访。

### 5.3 政治表述准确

涉及党和国家领导人重要论述、北京市领导讲话、重大决策部署时：

- 原则上按来源原文引用，不自行改造固定政治表述。
- “指出、强调、要求、表示、介绍”等引导词不得随意互换。
- 领导姓名和职务首次出现时写完整，后文可按原文使用姓名。
- 参加人员名单置于正文末段，不插入主要事实段。
- 不能凭经验增加“深入贯彻”“坚决落实”等表述。

### 5.4 数据可核验

所有数字必须能在来源中找到，包括但不限于：

- 时间范围和生效日期；
- 企业数量、产业规模、增速、投资金额；
- 参会单位数量和人员数量；
- 建设规模、算力规模、项目数量；
- 预警等级、响应等级和覆盖区域。

对“首个、首部、唯一、全国领先、全球首个、填补空白”等结论，只能在权威来源明确表达时使用，并保留其限定范围。

### 5.5 不植入公司角色

若原文没有公司参与信息，不得添加“中国电信北京公司积极参与”“为首都发展贡献力量”等内容。

若原文确实出现中国电信或北京公司，只能按原文写明其真实身份，例如“联合参与标准编制”，不得扩大为主导方或独家承担方。

## 6. 写作前必须收集的字段

| 信息组 | 必填内容 | 核验要求 |
|---|---|---|
| 栏目 | 北京动态 | 固定值 |
| 事件基础 | 事件名称、时间、地点 | 与原文一致 |
| 发布主体 | 市委、市政府、市级部门、机构或活动主办方 | 使用正式全称 |
| 人物信息 | 姓名、标准职务、参与方式 | 对照领导标准职务表或权威原文 |
| 核心事实 | 发布、召开、调研、预警、揭牌、成立等 | 明确已发生或计划发生 |
| 关键内容 | 目标、任务、措施、成果、数据 | 不遗漏限定条件 |
| 来源信息 | 来源媒体或单位、原文链接 | 链接必须真实 |
| OA 字段 | 供稿人、供稿部门、编辑、创建时间 | 由系统或用户提供 |

若缺少原文链接、核心事实或关键时间，不应直接生成可发布稿，应先输出“信息不完整，需补充”。

## 7. 标题规范

### 7.1 通用规则

- 固定以“【北京动态】”开头。
- 标题直接写最重要的事实，不另加栏目副标题。
- 优先包含主体、动作和核心结果。
- 领导活动类可使用“姓名＋活动＋核心要求”的结构。
- 政策类应区分“发布、印发、拟发布、征求意见、实施”等状态。
- 应急类标题应突出预警等级、时间范围、影响范围或响应级别。
- 可以保留必要数字，但数字必须准确。
- 不为追求传播效果增加感叹号；只有来源标题本身采用且栏目允许时才保留。

### 7.2 标题模板

```text
【北京动态】[发布主体]发布[政策/规划/标准名称]

【北京动态】北京[产业/领域][关键数据或重要进展]

【北京动态】[创新中心/工作组/平台名称]在京[揭牌/成立/上线]

【北京动态】[领导姓名]在[地点]调研[主题]，要求[核心要求]

【北京动态】市政府召开[会议名称] 研究[主要事项] [主持人及职务]主持会议

【北京动态】[预警或响应事实] [影响时间/范围] [应急响应级别]
```

### 7.3 禁止的标题写法

- “重磅！北京又有大动作”
- “震撼发布，未来已来”
- “北京全面进入人工智能新时代”
- “中国电信助力北京……”（原文未体现公司角色时）
- 把“拟发布”写成“正式发布”
- 把局部试点写成全市落地

## 8. 导语规范

导语用一段完成核心事实，通常回答以下问题：

1. 何时发生；
2. 谁发布、召开、调研或宣布；
3. 发生了什么；
4. 最重要的结果、目标或要求是什么。

导语不应一开始堆砌名单、背景政策和技术参数。

通用导语模板：

```text
[时间]，[发布主体/主办单位]在[地点或场合][发布/召开/揭牌/成立][事件名称]。[一句话写明核心内容、关键目标或主要结果]。
```

领导活动导语模板：

```text
[时间]，[领导标准职务][姓名]围绕[主题]到[地点]开展[调研/检查/慰问]。他/她强调，[按原文提炼核心要求]。[其他主要领导]一同参加。
```

应急信息导语模板：

```text
[发布时间]，[权威机构]发布[预警名称及等级]：预计[影响时段]，[影响区域]将出现[天气或风险情况]。[响应启动时间]，本市启动[响应级别]。
```

## 9. 正文组织规范

### 9.1 段落长度

- 一段集中表达一个主题。
- 一般每段 100 至 250 字；领导讲话和政策任务可适度增加。
- 原文较长时，优先保留与首都发展、信息通信、数字经济、人工智能、城市治理和民生安全相关的内容。
- 不得因压缩而删除关键限定条件、职责主体和风险提示。

### 9.2 层级表达

原文有清晰并列任务时，可使用：

```text
一是……
二是……
三是……
```

原文有主题分区时，可增加事实型小标题，例如：

```text
50余场论坛覆盖全产业链
新款人形机器人将首发
隆福寺街区打造数字潮市
```

小标题只能概括原文内容，不能添加原文没有的评价。

### 9.3 结尾

结尾按来源情况选择：

- 领导活动类：参加人员。
- 政策规划类：实施安排、后续计划或政策价值。
- 产业科技类：应用方向、生态建设或下一步安排。
- 应急信息类：公众防护、单位响应和注意事项。

正文之后单独列出：

```text
原文链接：[URL]
编辑:[姓名或工号]
```

不得自行增加“公司将认真贯彻落实”等公司表态。

## 10. 分类模板

### 10.1 市领导调研、检查类

适用：市委、市政府领导到区、园区、企业、项目、社区或公共设施调研检查。

```text
【北京动态】[领导姓名]在[地点]调研/检查[主题]，要求[核心要求]

[创建时间]
供稿人：[姓名]
供稿部门：[标准部门名称]
-----------------------------------------------------------------------
[事件日期]，[领导标准职务][姓名]围绕[主题]到[地点]开展[调研/检查]。他/她强调，[核心要求原意]。[其他主要领导]一同参加。

[点位一名称及定位]。[领导]察看/听取/了解[具体内容]。[领导]指出/要求，[与该点位直接相关的要求]。

[点位二名称及定位]。[现场事实]。[领导]指出/要求，[具体要求]。

[领导]在调研/检查时指出，[对整体形势、问题或发展方向的判断]。

[领导]强调/要求，一要[任务一]；二要[任务二]；三要[任务三]。[严格按原文保留任务主体、范围和程度]。

[参加人员及职务，按原文顺序]参加。

原文链接：[URL]
编辑:[姓名或工号]
```

写作要点：

- 按调研路线或检查点位顺序写。
- 每个点位采用“点位功能—现场动作—领导要求”的结构。
- 领导讲话不得改成智能体自行总结的政策结论。
- 现场描写仅保留来源已有内容，不虚构环境和人物动作。

### 10.2 重要会议类

适用：市委、市政府常务会议、专题会议、理论学习会议、警示教育大会、座谈会等。

```text
【北京动态】[会议名称]召开 [核心议题或要求] [主持人]主持会议

[创建时间]
供稿人：[姓名]
供稿部门：[标准部门名称]
-----------------------------------------------------------------------
[时间]，[会议主体]召开[会议全称]，研究/部署/学习[主要议题]。[领导标准职务][姓名]主持会议并讲话。[主要出席人员]出席。

会议指出/强调，[总体判断和会议主旨]。

会议研究[议题一]时指出，[主要内容和部署要求]。

会议强调，一要[任务一]；二要[任务二]；三要[任务三]。

会议还研究了[其他事项]。

[参加范围或人员]参加。

原文链接：[URL]
编辑:[姓名或工号]
```

写作要点：

- 会议有多个议题时，按原文顺序组织。
- “会议指出”和“会议强调”不能改成具体领导个人表述，反之亦然。
- 不删除“会议还研究了其他事项”等原文收束内容，除非确需制作摘要。

### 10.3 应急预警与城市安全类

适用：气象预警、汛期启动、应急响应、防汛部署和公共安全提示。

```text
【北京动态】[预警/响应核心事实] [影响时间和范围]

[创建时间]
供稿人：[姓名]
供稿部门：[标准部门名称]
-----------------------------------------------------------------------
[发布时间]，[发布机构]发布[预警名称及等级]：预计[起止时间]，[区域]将出现[风险情况]。

[响应时间]，本市启动[响应名称及级别]，[同步发布的指引或措施]同时对外发布。

按照[预案或权威文件名称]，[相关部门、单位、学校、企业或公众]应采取[核心响应行动]。

[对单位和公众最重要的防护提示，包括出行、停工停学、人员安置、值守、物资、信息报送等]。

原文链接：[URL]
编辑:[姓名或工号]
```

写作要点：

- 时间必须精确到原文所给粒度，不能把“7月10日14时至12日8时”简化成“近日”。
- 准确区分蓝色、黄色、橙色、红色预警及不同应急响应等级。
- 预报信息使用“预计、可能”，已启动措施使用“启动、发布”。
- 防汛检查类若以领导行程和讲话为主体，使用“市领导调研、检查类”模板。

### 10.4 政策、规划和标准发布类

适用：行动方案、行动计划、产业规划、地方标准、建设计划等。

```text
【北京动态】[发布主体]发布[文件全称] [可选：核心目标]

[创建时间]
供稿人：[姓名]
供稿部门：[标准部门名称]
-----------------------------------------------------------------------
[时间或“近日”]，[发布主体]发布/制定/拟发布[文件全称]。[文件生效时间、适用周期或总体目标]。

[文件]立足[背景或定位]，重点解决[问题]，围绕[核心方向]作出部署。

在目标方面，[目标一]；[目标二]；[目标三]。

在重点任务方面：
一是[任务一及责任主体]。
二是[任务二及实施路径]。
三是[任务三及应用场景]。
四是[任务四及保障机制]。

[文件的实施安排、试点示范、标准作用或预期价值]。

原文链接：[URL]
编辑:[姓名或工号]
```

写作要点：

- 文件名称第一次出现写全称，后续可使用原文给出的简称。
- 必须区分“正式发布”“拟发布”“将于某日实施”“框架规划”等状态。
- 目标年份、适用范围、主管部门、提出和归口单位不得遗漏。
- 标准类稿件要写清编制主体、参与单位、主要技术范围、解决的问题和实施日期。

### 10.5 产业、科技和经济进展类

适用：产业数据、创新中心揭牌、联盟或工作组成立、科技成果发布、产业大会和项目进展。

```text
【北京动态】北京[领域][核心进展或关键数据]

[创建时间]
供稿人：[姓名]
供稿部门：[标准部门名称]
-----------------------------------------------------------------------
[时间/场合]，[发布主体或权威来源]公布/发布/成立/揭牌[核心事件]。[用一句话写最重要的数据、成果或定位]。

[背景与主体信息：为什么建设、由谁牵头、有哪些参与单位、服务什么领域]。

该成果/平台/中心主要包括：
一是[能力或任务一]；
二是[能力或任务二]；
三是[能力或任务三]。

[关键数据、技术范围、产业链覆盖、代表性成果或应用场景]。

[后续方向、开放合作方式、产业价值或城市发展意义]。

原文链接：[URL]
编辑:[姓名或工号]
```

写作要点：

- 先写最有新闻价值的成果或数据，再解释背景。
- 多项成果可按“政策支撑—技术创新—算力—数据—场景”等原文逻辑分组。
- 机构成立类写清牵头单位、参与范围、组织目标和后续任务。
- 活动预告类写清时间、地点、主题、活动构成和公众可参与内容。

## 11. 人物、职务和部门名称规范

1. 人物首次出现时使用“标准职务＋姓名”，例如“市委副书记、市长殷勇”。
2. 同一人物有多个职务时，按来源原文和当前新闻场景选用，不自行增删排序。
3. 公司内部供稿部门名称必须查询合并 Excel 中的部门标准名称表。
4. 公司领导职务仅在稿件确实涉及公司领导时查询领导标准职务表；“北京动态”通常不应额外加入公司领导信息。
5. 来源中的北京市领导职务以权威原文为准，不能用公司领导表替代。
6. 无法确认职务时标记“待核实”，不得凭历史材料补全。

## 12. 语言风格规范

推荐：

- 客观、准确、正式、简洁。
- 以事实动词为主：召开、发布、印发、启动、成立、揭牌、调研、检查、提出、明确、部署。
- 适度使用政策和政务新闻固定表达，但必须有来源依据。
- 技术名词首次出现时说明其与场景的关系。

限制或禁止：

- 震撼、炸裂、逆天、王炸、刷屏等网络化表达。
- “全面领先”“遥遥领先”“必将彻底改变”等无证据结论。
- 连续堆叠“赋能、护航、筑牢、擘画”等宣传词。
- 把媒体评论、作者推断写成官方结论。
- 对政策效果作无来源预测。
- 对领导讲话进行口语化改写。

## 13. 事实冲突和缺失信息处理

- 多个来源的时间、数据或名称不一致时，列出冲突项并请求人工确认。
- 标题与正文不一致时，以权威原文为准，同时提示标题需修改。
- 原文链接缺失或无法确认时，不得生成虚假链接。
- 来源只有标题、字段占位符或空白正文时，不得用于写作和知识归纳。
- 现有语料中“北京数据集团发布‘京算Token工厂’”和“市政协12件提案聚焦‘人工智能赋能基础教育’”两个文件只有 `title`、`createDate`、`feedUnitName` 等占位字段，应视为无效样本。
- 同一新闻在不同压缩包中重复出现时，只保留一个有效版本。
- HTML 实体如 `&ldquo;`、`&rdquo;`、`&mdash;` 应还原为中文引号和破折号。

## 15. 智能体检索后的使用规则

当知识库检索到本文件时，智能体应按以下顺序工作：

1. 判断素材是否属于“北京动态”。
2. 在四种子类型中选择最匹配的一种。
3. 提取事件、人物、职务、单位、文件、数据、状态和来源链接。

6. 对缺失或冲突字段显式标记，不自行补造。
7. 执行成稿前检查清单。
