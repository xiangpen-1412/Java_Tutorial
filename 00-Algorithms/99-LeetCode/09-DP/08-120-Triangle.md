# 120. Triangle

> 难度：Medium  
> 主题：Dynamic Programming、一维状态压缩、遍历方向

## 问题

给定一个数字三角形，从顶点出发，每一步只能走到下一行中与当前位置相邻的两个位置，求从顶部到底部的最小路径和。

如果当前位于第 `i` 行、第 `j` 列：

```text
triangle[i][j]
```

下一步只能到达：

```text
triangle[i + 1][j]
triangle[i + 1][j + 1]
```

三角形第 `i` 行有 `i + 1` 个元素，因此该行的有效下标范围是：

```text
0 <= j <= i
```

题目中的 `O(n)` 额外空间指的是只使用一个长度等于行数的数组。三角形共有约 `n² / 2` 个元素，但任意一行最多只有 `n` 个状态，所以不需要保存整个二维 DP 表。

## 从上往下定义状态

定义：

```text
dp[j] = 到达当前行第 j 个位置的最小路径和
```

开始时只有三角形顶点：

```text
dp[0] = triangle[0][0]
```

处理第 `i` 行之前，`dp` 保存的是第 `i - 1` 行的结果。

对于当前行中间位置 `j`，它可能从上一行的两个位置到达：

```text
上一行 j - 1：左上方
上一行 j：    右上方
```

因此中间位置的转移为：

```text
dp[j] = min(dp[j - 1], dp[j]) + triangle[i][j]
```

## 两侧边界

每一行的最左侧和最右侧只有一个来源，不能直接套用中间位置的公式。

### 最左侧

`j == 0` 时，只能从上一行的 `dp[0]` 到达：

```text
dp[0] = dp[0] + triangle[i][0]
```

### 最右侧

`j == i` 时，只能从上一行的 `dp[i - 1]` 到达：

```text
dp[i] = dp[i - 1] + triangle[i][i]
```

### 中间位置

```text
dp[j] = min(dp[j - 1], dp[j]) + triangle[i][j]
```

结构如下：

```java
for (int i = 1; i < n; i++) {
    for (int j = i; j >= 0; j--) {
        int value = triangle.get(i).get(j);

        if (j == i) {
            // 最右侧：只来自左上方
        } else if (j == 0) {
            // 最左侧：只有一个来源
        } else {
            // 中间：比较左上方和右上方
        }
    }
}
```

## 为什么必须从右往左更新

状态压缩以后，上一行和当前行共用同一个 `dp` 数组。更新中间位置时，同时需要：

```text
旧 dp[j - 1]
旧 dp[j]
```

如果从左往右更新，计算 `dp[j]` 时，`dp[j - 1]` 已经被改成当前行的结果：

```text
需要：上一行的 dp[j - 1]
实际：当前行的 dp[j - 1]
```

状态来源因此被污染。

从右往左更新时，右侧位置先被修改，而当前计算需要的 `dp[j - 1]` 仍位于左侧，尚未更新，所以能够同时读取到上一行的两个旧状态。

可以把它记成：

```text
一维数组原地更新时，遍历方向必须保护尚未读取的旧状态。
```

这不是本题独有的技巧。在背包、网格路径和其他状态压缩问题中，也要根据依赖关系决定正序还是倒序。

## 为什么原来的循环进不去 `j == i`

原来的结构是：

```java
for (int i = 1; i < n; i++) {
    for (int j = 0; j < i; j++) {
        if (j == i) {
        }
    }
}
```

循环条件要求：

```text
j < i
```

因此循环体内的 `j` 永远不可能等于 `i`，`if (j == i)` 是不可达分支。

同时，第 `i` 行的下标范围是 `0` 到 `i`，使用 `j < i` 会漏掉最右侧元素。若只考虑下标范围，条件至少应为：

```java
j <= i
```

但使用一个数组原地更新时，还必须把遍历方向改成：

```java
for (int j = i; j >= 0; j--)
```

## 能否从左往右更新

可以，但不能在同一个数组中直接覆盖上一行状态。

如果坚持从左往右计算，需要分别保存：

```text
previous：上一行状态
current： 当前行状态
```

计算完一行后再交换两个数组。两个数组的长度都不超过 `n`，所以空间复杂度仍然是 `O(n)`，只是实现比一个数组倒序更新更繁琐。

这说明：

```text
O(n) 空间不等于只能使用一个数组；
两个长度为 n 的数组仍然是 O(n) 空间。
```

## 从下往上也是同一个 DP

另一种定义是：

```text
dp[j] = 从当前行第 j 个位置走到底部的最小路径和
```

从最后一行开始向上计算：

```text
dp[j] = triangle[i][j] + min(dp[j], dp[j + 1])
```

这个方向不需要单独处理左右边界，因此代码通常更短。

两种方向本质相同：

```text
从上往下：当前状态来自哪些前驱？
从下往上：当前状态可以选择哪些后继？
```

选择哪一种取决于哪种状态定义和边界处理更清楚。

## 最后返回什么

从上往下计算结束后，`dp` 中保存的是到达最后一行每个位置的最小路径和。

终点不是固定位置，因此不能直接返回：

```text
dp[0]
```

而应在最后一行的所有状态中取最小值：

```text
min(dp[0], dp[1], ..., dp[n - 1])
```

从下往上计算时，所有路径最终汇聚到顶点，因此答案位于：

```text
dp[0]
```

返回值的区别来自状态定义和计算方向，而不是两个算法求解了不同问题。

## 复杂度

三角形中的每个元素只处理一次：

```text
时间复杂度：O(n²)
```

只保存长度为 `n` 的一维状态：

```text
额外空间复杂度：O(n)
```

## 核心收获

- **识别信号**：每个位置只依赖相邻层中的少数状态，并要求所有路径中的最小值，可以定义“到达当前位置的最小路径和”。
- **状态压缩**：当前行只依赖上一行，不需要保留完整二维 DP 表。
- **遍历方向**：一个数组原地更新时，要从右往左计算，以免覆盖仍需读取的上一行状态。
- **边界来源**：最左侧和最右侧只有一个合法前驱，中间位置才有两个选择。
- **返回位置**：从上往下时答案是最后一行的最小值；从下往上时答案最终收敛到 `dp[0]`。
- **空间复杂度**：常数个长度为 `n` 的数组都属于 `O(n)`，不能把 `O(n)`误解为只能使用一个变量或一个数组。

## 我的思维误区

- **误以为 `O(n)` 空间无法保存三角形路径状态**：实际只需保存相邻一行，最大行宽就是 `n`。
- **先单独计算最左侧路径，却没有定义整个 `memo` 的状态含义**：最左侧只是边界，不能代表每一行的全部最优状态。应先用一句话定义 `dp[j]`，再写边界和转移。
- **使用 `j < i`，同时判断 `j == i`**：循环条件已经排除了 `j == i`，导致最右侧分支永远不会执行。
- **想从左往右原地更新**：这样会覆盖上一行的 `dp[j - 1]`。若要原地压缩，应倒序；若坚持正序，应使用独立的当前行数组。
- **没有先确定最终答案位于哪里**：从上往下时，最后一行每个位置都可能成为终点，因此需要取整行最小值。
