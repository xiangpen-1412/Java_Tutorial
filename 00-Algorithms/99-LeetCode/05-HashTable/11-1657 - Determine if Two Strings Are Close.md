# LeetCode 1657：Determine if Two Strings Are Close（确定两个字符串是否接近）

> 难度：Medium  
> 主题：字符频次、操作不变量、频次多重集合、数组哈希

## 1. 问题

给定两个只包含小写英文字母的字符串，长度各为 `1～100000`。可以在任一字符串内部不限次数执行两种操作，判断能否让两者相同：

- 交换任意两个位置的字符，不要求相邻。
- 选择当前字符串中已经存在的两种字母，将它们的所有出现同时互换。

例如第二种操作选择 `a、b`：

```text
aacabb → bbcbaa
所有 a 变成 b，同时所有 b 变成 a，c 不变。
```

它不能只改某一次出现，不能增加字符，也不能从另一个字符串借用字母。`aacabb` 中没有 `e`，因此不能选择 `a、e` 进行交换。

## 2. 识别信号：从模拟操作转向寻找不变量

题目问的是能否转换，不要求操作步骤或最少操作次数。可以先观察每种操作改变什么、保留什么，再判断目标是否可达。

| 操作 | 能改变什么 | 保留什么 |
| --- | --- | --- |
| 交换两个位置 | 字符排列顺序 | 每种字母的次数 |
| 整体互换两种已有字母 | 哪个字母对应哪个次数 | 已有字母种类，以及各个频次的数量分布 |

第一种操作能任意重排字符；第二种操作能交换字母对应的频次。例如 `a:3、b:2` 可以变成 `a:2、b:3`，但不会把频次 `3、2` 拆成其他数。

## 3. 我的推导与关键修正

最初想到分别统计字母次数，再把次数排序比较。这个方向正确，但当时认为“字母是什么不重要”，遗漏了只能交换已有字母的限制。

```text
cabbba：c:1，a:2，b:3
eddfff：e:1，d:2，f:3
```

两边频次都是 `[1,2,3]`，却不能转换：第一边的 `a、b、c` 无法变成从未出现过的 `d、e、f`。

准确的理解是：**具体哪个字母对应哪个次数可以改变，但有哪些字母存在不能改变。**

因此最终判断需要同时满足：

1. 两个字符串出现过的字母集合相同。
2. 两边频次排序后相同，重复频次必须保留。

例如：

```text
cabbba：a:2，b:3，c:1
abbccc：a:1，b:2，c:3

字母集合都为 {a,b,c}
排序后的频次都为 [1,2,3]
```

这组可以转换，不要求同一个字母原本的次数就相同。

## 4. 为什么这两个条件足够？

必要性来自操作限制：位置交换不改变次数，整体换字母只交换已有频次，也不能引入新字母。

充分性则要回答“条件相同后，真的能变过去吗”：

- 频次能一一配对，就能通过反复整体交换已有字母，让每种字母获得目标次数；任意有限的重排都能分解为若干次两两交换。
- 当每种字母的次数与目标一致后，再通过位置交换排成目标字符串。

所以不需要真的模拟这些操作。这里保存的频次是字符串的组成特征，不是 350、383 那种逐个消耗的库存。

## 5. 已通过的 Map + List 方法

自己的实现建立两个 `Map<Character, Integer>` 统计频次，然后比较 key 集合，将 values 复制到 List 排序后比较。截图显示通过全部 169 个测试。

相关 API 分清职责即可：

| 写法 | 含义 |
| --- | --- |
| `map.keySet()` | 所有 key 的 Set，HashMap 没有 `keys()` 方法 |
| `map.values()` | 所有 value 的 Collection，允许重复 |
| `map.entrySet()` | 键值对集合，每项用 `getKey()`、`getValue()` 读取 |
| `map1.keySet().equals(map2.keySet())` | 集合元素相同即可，忽略顺序 |
| `new ArrayList<>(map.values())` | 将频次复制到可排序的列表中 |
| `counts1.equals(counts2)` | 比较长度及每个位置的值，因此先排序再比较 |

直接比较两个 Map 是否相等，会额外要求同一字母的次数相同，条件过强。直接比较未排序的频次 List，则会受到排列顺序影响。

### 为什么频次不能放进普通 Set 比较？

本题需要频次的多重集合：不仅关心有哪些次数，还关心每个次数出现几回。

例如两个字符串都含五种相同字母，频次分别为：

```text
[1,1,2,3,3]
[1,2,2,2,3]
```

总长度都为 10，转成普通 Set 也都得到 `{1,2,3}`，但频次分布不同，无法通过交换获得。使用排序后的 List 或数组，就不会丢失重复项。

### List 排序与 Comparator

```java
Collections.sort(counts);                  // 升序，Collections 有 s
counts.sort(Integer::compare);            // 同样是升序
counts.sort((a, b) -> Integer.compare(b, a)); // 降序
```

Comparator 返回负数表示第一个参数 `a` 排在 `b` 前面，正数表示排在后面，零表示在此排序规则下相等。两边使用相同排序方向即可。

自己写的 `a - b` 在本题频次范围内不会溢出，因此不是错误；通用整数比较优先使用 `Integer.compare`。

## 6. 性能优化：保留判断逻辑，换成固定字母表

截图中的 Map 版本耗时 66 ms。单次计时无法精确归因，但统计每个字符都进行 HashMap 查询和更新，并涉及包装类型转换；计数增大后还可能分配新的 Integer 对象。

题目只含 `a～z`，可以用两个 `int[26]` 表示频次，通过 `字符 - 'a'` 定位。优化后的逻辑仍是原来的两个条件：

```text
先逐下标检查：两边对应字母是否同时出现或同时不出现
再分别排序频次数组，比较排序后的内容
```

**字母种类必须在排序前检查。** 排序前下标表示字母，排序后下标只表示排序位置，原来的字母身份已经丢失。未出现字母对应的零可以一起排序，两边都有固定的 26 项。

另外可以先检查长度，不同则直接失败；用 `charAt(i)` 顺序读取可避免 `toCharArray()` 复制整个字符串。数组内容比较使用 `Arrays.equals`，不要把 List 的 `.equals()` 用法直接照搬到数组对象上。

设字符串长度为 `n、m`：

- Map 版本平均时间为 `O(n + m + 26 log 26)`，即 `O(n + m)`；每个频次 List 最多 26 项，排序不是随字符串长度增长的大开销。
- 数组版本仍为 `O(n + m)`，主要减少哈希、装箱及对象分配的常数开销。
- 原实现含两个 `toCharArray()` 副本，辅助空间为 `O(n + m)`；使用固定频次数组并直接读取 String 时，辅助空间为 `O(26) = O(1)`。

## 7. 可迁移的思考方式

遇到“允许若干操作，判断能否转换”的题，先区分能变化的部分与不变量。本题中位置可以重排、频次可以在字母之间交换，但字母集合和频次多重集合保持不变。

比较前还要明确是否允许丢失信息：对 key 去重合理，对频次去重会丢掉次数分布；排序频次能统一顺序，但也会丢失字母与频次的对应关系，所以先完成依赖字母身份的检查。
