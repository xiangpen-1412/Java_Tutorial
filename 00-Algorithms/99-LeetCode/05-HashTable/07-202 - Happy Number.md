# LeetCode 202：Happy Number（快乐数）

> 难度：Easy  
> 主题：状态转换、HashSet 判环、数位拆分、快慢指针

## 1. 问题

给定正整数 `n`，反复把它替换为各位数字的平方和。如果最终到达 `1`，返回 `true`；如果进入不包含 `1` 的循环，返回 `false`。题目范围是 `1 <= n <= 2^31 - 1`。

```text
19 → 1² + 9² = 82 → 68 → 100 → 1
```

## 2. 本次遇到的问题：数值大小不等于位数

最初写了 `new int[n]`，先把各位数字存进去，再遍历数组计算平方和。输入 `1999999999` 时出现 Memory Limit Exceeded。

这个数只有 10 位，代码却申请了约 20 亿个 `int`。每个 `int` 占 4 字节，仅数组元素就需要约 8 GB。即使 `size` 最后只增加到 10，已经分配的其余位置仍占空间。

应先问“我要保存多少项数据”，再决定数组长度。这里要保存的是数位，不能用整数本身的值决定容量。

进一步观察：取出一个数位后，只需要它对平方和的贡献，不会再单独使用它，因此可以当场累计，省掉数位数组。

```text
remaining = 19，sum = 0
取末位 9 → 累加 9 × 9，sum = 81；去掉末位，remaining = 1
取末位 1 → 累加 1 × 1，sum = 82；去掉末位，remaining = 0
```

拆位使用 `% 10` 和整数除法 `/ 10`。平方用 `digit * digit` 即可，无需调用返回浮点结果的 `Math.pow`。

## 3. 核心模型：完整数字就是状态

原来的 HashSet 判环思路是正确的。集合应记录每轮的完整数字，例如 `82、68、100`，而不是拆出来的单个数位。

关键性质是：**同一个数字的下一步结果固定不变。** 因此再次遇到同一状态，后面必然重复之前的过程。

```text
2 → 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → …
```

第二次遇到 `4` 时，无需继续验证整个环，之后一定又会走向 `16、37……`。

一种清楚的遍历约定是：集合只保存已经处理过的状态；每轮先检查是否为 `1`、是否出现过，再记录并计算下一状态。这是“把重复过程变成状态查询”的具体应用。

## 4. 为什么不会一直产生新的大数字？

本题的正 `int` 最多有 10 位，每位平方最多为 `81`，所以一次转换后的结果不超过 `810`。进入这个范围后，数字最多三位，下一步不超过 `243`，之后仍留在有限范围内。

在有限状态中持续执行确定的转换，必然出现重复；`1 → 1` 本身也是一个环。于是只需区分到达 `1`，还是落入其他循环。

## 5. 快慢指针作为进一步的空间优化

每个数字只有一个固定后继，可以把这个过程看作一条隐式链表：慢指针每轮转换一次，快指针转换两次。进入同一个环后，快指针每轮比慢指针多前进一个位置，最终会相遇。

- 相遇于 `1`：快乐数。
- 相遇于其他状态：进入非快乐数循环。
- 如果两者从同一个 `n` 开始，必须先推进再判断相遇，初始相等不算检测到环。

HashSet 直接保存访问历史，更容易解释；快慢指针只保存两个数字，省去状态集合，但会做更多转换，不保证实际运行一定更快。

设初始数字有 `d` 位，后续到结束或重复前处理 `T` 个状态：利用本题状态迅速缩小的性质，HashSet 方法平均时间可记为 `O(d + T)`，保存 `O(T)` 个状态；快慢指针使用固定数量变量。对于本题固定的 Java `int` 范围，`d` 和后续状态数量都有固定上界。递归还会占调用栈，每轮只有一个后继时可直接用循环表达。

## 6. 可迁移的判断

- 需要反复模拟、且同一状态决定同一后继时，可以用已访问状态判断循环。
- 中间数据只用于累计结果时，考虑边读取边累计，避免完整保存。
- 先估算容量与单项大小，再申请数组；数值范围和数据项数量是不同的概念。
- 如果后继还依赖方向、位置等其他变量，判重状态也必须包含这些信息，不能只记录一个不完整的数值。
