# LeetCode 36：Valid Sudoku（有效的数独）

> 难度：Medium  
> 主题：分区域去重、HashSet、矩阵分块、坐标换算

## 1. 问题

给定 `9 × 9` 的 `char[][] board`，检查已填的 `'1'～'9'` 是否在同一行、同一列或同一个固定 `3 × 3` 宫格内重复。`'.'` 是空格，跳过。只验证当前约束，不填数，也不需要判断棋盘最终是否有解。

同一个数字可以出现在不同区域，只要不违反任意一条行、列、宫约束。

## 2. 从逐个搜索变成分区域记录

最初想对每个数字重新搜索整行、整列和宫格。可以改成记录“这个区域已经见过哪些数字”：读到新数字时，查询记录；出现过就说明冲突，否则加入。

每个区域的集合只保存该区域已扫描的非空数字。两个重复数字总有一个先被读到，后读到的那个会发现记录，因此只检查过去不会漏掉未来的重复。

实际实现中，行、列检查已经正确：外层固定 `i`，内层通过 `board[i][j]` 扫第 `i` 行，通过 `board[j][i]` 扫第 `i` 列，使用两个独立 Set，每轮外层重新创建。宫格也应每换一个区域就重新创建 Set。

## 3. 宫格坐标：起点加偏移

四层循环可以清楚地区分两组坐标：

```text
i、j：宫格处于第几排、第几列，范围 0～2
x、y：宫格内部的行、列偏移，范围 0～2

row = i * 3 + x
col = j * 3 + y
```

例如中间宫格 `i = 1、j = 1`，起点为 `(3,3)`，加上内部偏移后覆盖行 `3～5`、列 `3～5`。

最初使用 `x * (i + 1)`、`y * (j + 1)`，实际上改变了访问间隔，没有移动到对应区域起点。例如 `i = 1` 时行坐标变成 `0、2、4`，应当是 `3、4、5`。这种写法会把不同宫格的格子混入同一个 Set，误报重复，也会漏查格子。

可复用的公式是：

> 全局坐标 = 区域起点 + 区域内部偏移。

## 4. 不想使用四层循环时，怎样转换？

给九个宫格和宫格内部九个位置都按行编号：

```text
0 1 2
3 4 5
6 7 8
```

宽度为 3 时，一个编号对应的二维坐标是：

```text
行 = 编号 / 3
列 = 编号 % 3
```

让 `i = 0～8` 表示宫格编号，`j = 0～8` 表示宫格内部编号，就得到：

```text
row = (i / 3) * 3 + j / 3
col = (i % 3) * 3 + j % 3
```

例如 `i = 5`，宫格起点为 `(3,6)`；`j = 7`，内部偏移为 `(2,1)`，最终访问 `(5,7)`。

这可以直接融入原来的行列循环：每轮 `i` 创建三个独立 Set，内层 `j` 同时检查第 `i` 行、第 `i` 列和第 `i` 宫格。四层与两层写法都可用，按自己能清楚解释的坐标含义选择。

## 5. 循环层数不等于实际复杂度

宫格检查的四层循环都只执行 3 次：

```text
3 × 3 × 3 × 3 = 81 个格子
```

合并成两层则是 `9 × 9 = 81` 个宫格位置，访问量相同；再加行、列两组检查，总体仍只是棋盘的固定几次扫描。减少代码嵌套并未减少渐进复杂度。

本题大小固定为 `9 × 9`，严格分析时间、辅助空间均有固定上界，记为 `O(1)`。若推广为 `N × N` 的合法分块棋盘，按区域记录可在平均 `O(N²)` 时间检查；逐个数字重新搜索所在行列宫会达到 `O(N³)` 量级。应计算总访问次数，而非直接用 for 的层数当指数。

## 6. 状态范围

- 需要记录“某个区域中出现过没有”，普通 Set 或布尔数组就足够，不需要频次计数。
- 状态隐含了区域身份。同一个数字在不同区域可合法重复，不能只用一个全局数字集合。
- `Set.add()` 首次加入返回 `true`，重复加入返回 `false`，可以合并查询与记录。

本题应保留的主要收获是：分清每份状态属于哪个区域，以及用“起点 + 偏移”推导矩阵子区域坐标。

## 7. 本题涉及的 Java 字符与集合

### 单引号、双引号与实际类型

LeetCode 测试数据可能展示为 `[["5", "."], ...]`，这是序列化输入的展示方式。方法参数是 `char[][] board`，实际访问 `board[row][col]` 得到的就是 `char`。

在 Java 源码中，`'5'`、`'.'` 是字符字面量，`"5"`、`"."` 是 String。检查空格应比较 `board[row][col] == '.'`。

### Set<Character> 可以直接接收 char

泛型参数必须是引用类型，所以使用 `Set<Character>`，不能写 `Set<char>`。但传入的值可以是基本类型，编译器会自动装箱：

```java
char digit = '5';
Set<Character> seen = new HashSet<>();
seen.add(digit);      // 自动装箱，效果相当于 Character.valueOf(digit)
seen.contains(digit); // 同样可直接传 char
```

`add` 首次加入返回 `true`，已有相等元素则返回 `false`。Set 根据元素的相等性判断重复，调用者不必手动比较每个 Character。

### char 用 == 比较，没有 equals 方法

`char` 是基本类型，没有对象方法，两个 `char` 用 `==` 比较值。两个非空 `Character` 可以用 `.equals()` 比较字符值；两个包装对象之间的 `==` 比较引用，不能用小字符值下缓存造成的结果推断所有情况。

字符的整数表示是编码值，例如 `'5'` 对应数值 `53`；需要数字值 `5` 时，可以计算 `'5' - '0'`。字符类型与表示次数的计数类型也要分开：频次应使用 `int`，本题采用字符只是为了记录原始棋盘内容。
