# LeetCode 454：4Sum II（四数相加 II）

> 难度：Medium  
> 主题：HashMap、两数和频次、折半枚举、预处理查询

## 1. 问题

给定四个长度均为 `n` 的整数数组，从每个数组中各选一个元素，统计有多少组下标 `(i, j, k, l)` 满足：

```text
nums1[i] + nums2[j] + nums3[k] + nums4[l] = 0
```

返回选法数量。不同下标即使对应相同数值，也算不同选法；四个下标分别属于四个数组，可以相等。不同选法相互独立，同一个元素可以参与多组选法，不会被用完。

题目保证 `1 <= n <= 200`，元素范围为 `[-2^28, 2^28]`，包括正数、负数和零。

## 2. 分类与识别信号

本题归入 **HashMap / HashSet** 分类，具体方法是“两两分组求和 + HashMap 频次统计”，也称折半枚举（meet-in-the-middle）。输入是数组，而笔记按主要解题方法归类。

识别信号：

- 需要从多个独立数组中各选一个元素，直接枚举的组合数量相乘。
- 约束只依赖于总和，可以拆成两个部分；一半确定后，只需要知道另一半能否凑出指定的和，以及有多少种选法。
- 目标是统计选法数量，因此仅记录某个和是否存在不够，需要保存频次。

## 3. 我的起点：回溯或四层循环

最初考虑回溯，随后写出了四层 `for`，枚举所有组合并在总和为零时计数。逻辑正确，两者都要枚举 `n^4` 种组合。

```text
n = 200 时：200^4 = 1,600,000,000，约 16 亿种组合
```

由于包含负数，当前总和大于零也不能直接剪枝，后面的负数可能将其抵消。仅把四层循环改成递归不会减少枚举量。

## 4. 找到重复工作：固定前半组后，后半组在回答什么？

设前两个数是 `a、b`，后两个数是 `c、d`：

```text
a + b + c + d = 0
等价于
c + d = -(a + b)
```

固定 `i、j` 后，最里面两层循环实际上在回答：

> 后两个数组中，有多少对元素的和等于 `-(a + b)`？

例如两种不同的前半组选法都得到和 `3`，原代码就会两次完整扫描后半组，寻找和为 `-3` 的配对。后两个数组没有变化，这个问题的答案也没有变化，可以提前计算并保存。

## 5. Map 记录什么，为什么必须保存数量？

先枚举 `nums3、nums4` 的全部下标配对，建立：

```text
key   = 两个元素的和
value = 产生这个和的下标配对数量
```

例如：

```text
nums3 = [1, 2]
nums4 = [2, 1]

1 + 2 = 3
1 + 1 = 2
2 + 2 = 4
2 + 1 = 3

统计结果：2 → 1，3 → 2，4 → 1
```

若当前 `a + b = -3`，就查询 `3`，答案直接增加 `2`，而非只增加 `1`。每一对满足要求的后半组，都能与当前前半组组成一个不同的合法四元组。

每个四元组都唯一地拆成前半组 `(i, j)` 和后半组 `(k, l)`，所以这种累计不会漏计或重计。下一对前半组如果仍然需要和 `3`，仍可增加 `2`，**Map 中的频次不减少**。

## 6. 从 O(n⁴) 到 O(n²) 的推导

原方法中，两部分嵌套执行：

```text
前半组 n² 种 × 每次重新枚举后半组 n² 种 = n⁴
```

预处理后，两部分顺序执行：

```text
建立后半组频次表：n² 次配对，平均每次更新 O(1)
枚举前半组并查询：n² 次配对，平均每次查询 O(1)

平均总时间：O(n² + n²) = O(n²)
最坏额外空间：O(n²)，最多保存 n² 种不同的和
```

这里应说“HashMap 查询平均为 `O(1)`”，而非“无限趋近于 `O(1)`”；它不是随着输入增大逐渐变成常数，也不保证最坏情况一定为常数。

内部两层循环的工作并未消失，而是只提前统一执行一次。优化关键是将重复枚举转换为预处理后的查询，使原本相乘的工作量变成相加。

## 7. 与频次消耗题的区别

| 题目 | 频次代表什么 | 匹配后是否减一 |
| --- | --- | --- |
| [[02-350 - Intersection of Two Arrays II]] | 还剩多少个元素可以配对 | 是，每个元素只能被使用一次 |
| [[03-383 - Ransom Note]] | 某种字母的剩余库存 | 是，构造时会消耗字母 |
| 454 | 有多少种后半组选法能产生这个和 | 否，各个四元组独立计数，可以复用同一后半组 |

不要看到频次表就机械地减一，要先判断它表达的是可消耗资源，还是可复用的选法数量。

## 8. 变种与注意点

- 目标和改为 `target` 时，查询的补数变为 `target - (a + b)`，其余推导相同。
- 相同值位于不同下标时必须分别计数，不能用 Set 去重两数和而丢掉频次。
- 本题没有跨数组的下标互斥要求；若改成从同一个数组选择四个不同位置，就需要额外处理下标冲突及重复计数，不能直接套用此拆分方式。
- 当前数值范围下四数和能放入 Java `int`，答案最多为 `200^4 = 1,600,000,000`，也能放入 `int`；范围扩大后应重新检查是否需要 `long`。
- 只需为一半建立频次表，另一半边枚举边查询即可，不要求同时创建两张 Map。

## 9. 下次如何想到这种优化？

遇到多层枚举时，先固定外层，解释内层究竟在回答什么问题。如果答案只依赖于一个可计算的特征，例如“所需的两数和”，就考虑预先保存“特征 → 答案”，供外层查询。

本题从原始数字进一步走到了组合特征：**Map 的 key 可以是计算得到的和，value 可以是产生这个和的选法数量。**
