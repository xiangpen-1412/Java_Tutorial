# LeetCode 149：Max Points on a Line（直线上最多的点数）

> 难度：Hard  
> 主题：固定基准点、HashMap 分组、斜率规范化、GCD  
> 本次完成：自己的 `double` 斜率版本修正后通过；GCD 版本作为进一步理解的精确表示。

## 1. 问题与识别信号

给定二维平面上的整数坐标 `points[i] = [x, y]`，返回同一条直线上最多有多少个点。直线可以是水平、竖直或倾斜的；只返回点数，不需要返回直线。题目保证 `1 <= n <= 300`，坐标范围为 `[-10^4, 10^4]`，所有坐标点互不重复。[原题与约束](https://leetcode.com/problems/max-points-on-a-line/description/)

两个不同的点确定一条直线。固定其中一个点后，其他点是否与它共线，就可以转成“相对于这个基准点，斜率是否相同”。由此想到：枚举基准点，再用 HashMap 对方向计数。

## 2. 固定一个点，才能用斜率代表同一条直线

设基准点为 `(x1, y1)`，另一个点为 `(x2, y2)`：

```text
dx = x2 - x1
dy = y2 - y1
斜率 = dy / dx
```

上下相减的顺序必须一致。`dx == 0` 表示竖直线，普通斜率不存在；`dy == 0` 且两点不同表示水平线。

仅仅斜率相同的两条线可能平行；这里还固定了同一个基准点，因此相同斜率才意味着同一条直线。这也决定了 Map 的作用范围：**每换一个基准点，就重新创建 Map，不能跨基准点累计方向次数。**

```text
key   = 相对当前基准点的斜率或规范化方向
value = 当前方向上其他点的数量
这条线上的点数 = value + 1（基准点自身）
```

只有一个点时，Map 为空，但答案仍为 1。原代码把 `+1` 放在遍历 Map 的循环里，空 Map 根本不会执行这一步，因此 `[[0,0]]` 返回了 0。基准点本身的数量应体现在初始答案中，而不能依赖发现另一个点后才计入。

## 3. 自己的 double 版本：公式对，表示方式也要对

第一次用 `int` 保存斜率，两个整数相除会截去小数部分。以 `(0,0)` 为基准，`(2,1)` 和 `(3,1)` 的斜率分别是 `1/2`、`1/3`，整数除法却都得到 0，三个不共线的点就被合并到同一个 key。

需要在除法前转换操作数，并让 Map 的 key 使用 `Double`：

```java
double slope = dx == 0 ? Integer.MAX_VALUE : (double) dy / dx;
if (slope == 0.0) slope = 0.0;
```

竖直方向单独使用统一标记。原来的 `Integer.MAX_VALUE` 在本题坐标范围内不会与真实的非竖直斜率冲突；也可以用 `Double.POSITIVE_INFINITY` 表达其特殊含义。

修正整数除法后，又在 `[[2,3],[3,3],[-5,3]]` 上得到 2，而正确答案是 3。以 `(2,3)` 为基准，另外两点分别产生 `0.0 / 1 = 0.0` 和 `0.0 / -7 = -0.0`。

数学上两者都表示水平线，但 `HashMap<Double, ...>` 会把正零、负零当成不同的 key。`if (slope == 0.0) slope = 0.0;` 利用数值比较时两者相等，把它们统一写成正零。这一行并非无意义的自我赋值。

整数除法的转换时机，以及基本类型比较与 `Double.equals` 的区别，统一记在 [[10-Integer Division & Double Keys]]。本题已经通过的 `double` 版本可以保留；下面的整数对表示用于理解如何精确设计 key。

## 4. 为什么只遍历 j > i，不需要 visited？

原代码把已处理的基准点放入 `Set<Point>`，内层仍扫描全部点，再跳过集合里的点。在题目保证坐标互不重复时，这种跳过逻辑本身成立。

直接按下标遍历能表达同一件事：

```text
for 每个基准点 i：
    新建 Map
    for j 从 i + 1 到 n - 1：
        计算方向，累计该方向点数
        用“方向计数 + 1”更新答案
```

不会漏解的原因：任取一组共线点，其中下标最小的点作为基准点时，其余点都在它后面，那一轮就能统计完整。后续基准点无需再向前补数。

由此可以省掉 `Point` 对象创建、Set 查询和对前面点的重复检查；更新计数时直接更新最大值，也不必事后遍历 Map。若已有答案 `res >= n - i`，剩余基准点最多只能在后缀中统计这么多点，可以提前结束。

这些优化减少额外工作，最坏时间复杂度仍是 `O(n²)`。原来的“固定一点 + 统计斜率”已经是标准框架，不能只凭一次提交的运行排名判断是否选错算法。

## 5. GCD 的用途：把同一个斜率约分成同一个 key

GCD（Greatest Common Divisor）是最大公约数，即能同时整除两个整数的最大正整数。例如 `gcd(6,8) = 2`，因为 6 和 8 的共同正约数是 1、2。

本题可以保存最简分数的分子、分母，不必真正做小数除法。以下整数对统一按 `(dy, dx)` 排列：

| 原始 `(dy, dx)` | GCD | 约分结果 |
| --- | --- | --- |
| `(6,8)` | 2 | `(3,4)` |
| `(9,12)` | 3 | `(3,4)` |

两个方向的真实斜率相同，约分后得到相同的整数对，便能可靠地归入同一个桶。可用 `record Slope(int dy, int dx) {}` 表达这个 key，生成的相等比较会同时比较两个分量。

### 怎样计算 GCD：辗转相除

每一轮把 `(a,b)` 换成 `(b,a % b)`。旧除数成为新的被除数，余数成为新的除数，直到余数为零。

完整例子：求 `gcd(1071,462)`。

```text
1071 = 462 × 2 + 147  → 下一轮求 gcd(462,147)
 462 = 147 × 3 +  21  → 下一轮求 gcd(147,21)
 147 =  21 × 7 +   0  → 下一轮为 (21,0)，停止，返回 21
```

第一轮的余数 147 只是下一轮的输入，还不是答案。零表示已经除尽；返回的是最后一个能除尽的除数 21，更新变量后它位于 `a` 中。

**为什么可以换两个数？** 看 `1071 = 462 + 462 + 147`。假设某个长度 `d` 能把 1071 和 462 都分成完整的小块，那么从 1071 中拿走两段 462，剩下的 147 也必然由完整小块组成。反过来，如果 `d` 能整除 462 和 147，也就能整除它们拼成的 1071。因此两组数的全部公约数相同，最大的公约数当然也不变。

```java
private int gcd(int a, int b) { // 传入非负数
    while (b != 0) {
        int remainder = a % b;
        a = b;
        b = remainder;
    }
    return a;
}
```

余数总小于当前正除数，所以数值不断缩小，最终会结束。无需事先保证 `a >= b`；`gcd(6,8)` 第一轮就会变成 `gcd(8,6)`。一项为零时也成立，例如 `gcd(0,7) = 7`。

### 约分后还要统一符号

`(dy,dx) = (2,4)` 和 `(-2,-4)` 表示同一条直线上相反的两个方向。只约分会留下 `(1,2)`、`(-1,-2)` 两个 key，因此还需要统一符号：普通方向保证 `dx > 0`，竖直方向保证 `dy > 0`。

```java
int g = gcd(Math.abs(dy), Math.abs(dx));
dy /= g;
dx /= g;

if (dx < 0 || (dx == 0 && dy < 0)) {
    dx = -dx;
    dy = -dy;
}
```

这样水平线自然统一为 `(0,1)`，竖直线统一为 `(1,0)`，负斜率保留负的 `dy`。整数零没有正负零之分，也不需要把竖直线伪装成某个很大的普通斜率。

题目保证坐标不重复，所以 `dx`、`dy` 不会同时为零，`g` 不会为零。当前坐标差最多为 20000，差值和取绝对值使用 `int` 足够。

## 6. 复杂度、变种与复习判断

- `double` 方向表：枚举 `O(n²)` 个点对，哈希操作按平均常数时间计算，总平均时间为 `O(n²)`，额外空间为 `O(n)`。
- GCD 方向表：计入每次约分，时间为 `O(n² log M)`，`M` 是最大坐标差的量级；固定坐标范围下通常简记为 `O(n²)`，额外空间仍为 `O(n)`。它的价值是精确、统一的 key 表示，不保证每次运行都比 `double` 版本更快。
- 若变种允许重复坐标，应单独统计与基准点重合的点，将其数量加到各方向结果中；不能用坐标 Set 直接消掉，也不能对 `(0,0)` 求约分后直接相除。
- 若需要返回直线，可以同时记录取得最大值时的基准点和规范化方向。若脱离固定基准点而全局统计直线，仅保存斜率就不够，还必须区分位置不同的平行线。

本次真正需要纠正的判断是：基准点即使没有搭档也算一个点；数学上同一个斜率必须对应同一个程序 key；性能优化先检查重复扫描与对象开销，而不是只看循环层数。复习 GCD 时，应能自行说明“取余为什么保留全部公约数”和“为什么最后返回非零的那个数”。
