# LeetCode 128：Longest Consecutive Sequence（最长连续序列）

> 难度：Medium  
> 主题：HashSet、双向扩展、已处理状态、避免重复搜索、总工作量分析

## 1. 问题

给定无序整数数组 `nums`，返回能组成的最长连续整数序列的长度。连续指相邻数值相差 `1`，不要求这些数字在原数组中相邻或保持原顺序；重复数字不增加长度。空数组返回 `0`。

```text
[100, 4, 200, 1, 3, 2] → 连续段 [1, 2, 3, 4]，长度 4
[1, 0, 1, 2]          → 连续段 [0, 1, 2]，长度 3
```

题目要求 `O(n)` 时间，数组长度最多 `10^5`，数值范围为 `[-10^9, 10^9]`。比较排序通常需要 `O(n log n)`，不能满足要求。

## 2. 从直接方法找到优化方向

最直接的过程是：选一个数，不断查询相邻整数是否存在，直到连续段断开。这里有两个需要分别解决的问题：

- **单次查找慢**：反复扫描数组找某个数，可以用 HashSet 将存在性查询变成平均 `O(1)`。
- **同一段被反复搜索**：即使查询快，从每个数字重新扩展仍可能是平方级工作量，还需要避免重复展开。

最初想先找到最小值，再搜索它所在的段。但无序数组、普通 HashMap 或 HashSet 不支持常数时间取最小值，通常需要扫描；本题也不需要统计出现频率，只关心数字是否存在。

## 3. 我自己的方法：从任意起点向两边扩展

不必先找最小值。建立两个集合：

```text
set     = 输入中存在的所有不同数字
visited = 已经纳入某次连续段搜索的数字
```

按原数组顺序遍历：当前数字已处理就跳过；否则标记当前数字，长度从 1 开始，分别向 `num + 1` 和 `num - 1` 扩展，找到一个就标记并增加长度。两边都断开后更新最大长度。

例如：

```text
[100, 4, 200, 1, 3, 2]

从 100 出发：99、101 不存在，长度 1
从 4 出发：向下找到 3、2、1，向上没有 5，长度 4
从 200 出发：199、201 不存在，长度 1
后续 1、3、2：已处理，直接跳过
```

每次扩展结束时，起点所在的整段连续数字都已被标记。两个完整的连续段不可能部分重叠：若能通过相邻整数连起来，它们本来就是同一段。因此从后续未处理的数字出发，会搜索另一段；已经标记的数字无需重新出发。

## 4. 第一次超时：记录了 visited，却没有查询它

第一版只在扩展过程中调用 `visited.add(...)`，外层仍然从每个数字启动搜索。对于 `[1, 2, 3, 4]`：

```text
从 1 出发：找 2、3、4
从 2 出发：找 3、4 和 1
从 3 出发：找 4 和 2、1
从 4 出发：找 3、2、1
```

一整段长度为 `n` 时，每次都会找到另外 `n - 1` 个数字，总工作量约为 `n(n - 1)`，仍是 `O(n²)`。

教训是：**维护状态必须影响后续执行。只保存“见过”，却不据此跳过搜索，不会减少重复工作。**

## 5. 第二版通过但很慢：漏掉起点自身的标记

第二版加了外层跳过判断，但只标记 `larger`、`smaller`，没有标记起点 `num`。例如：

```text
nums = [1, 1, 1, 2, 3, 4]

第一个 1：搜索 2、3、4，visited = {2, 3, 4}
第二个 1：1 没被标记，重复搜索整段
第三个 1：再次重复搜索整段
```

如果最先搜索的起点重复 `k` 次，所在连续段有 `m` 个不同数字，就可能产生 `O(k × m)` 的扩展工作，最坏仍可达到 `O(n²)`。测试通过不等于复杂度已经达标，也不能把明显的重复搜索简单归因于平台计时波动。

外层入口需要同时完成“跳过”和“标记当前起点”：

```java
if (visited.contains(num)) {
    continue;
}
visited.add(num);
```

随后保留原来的双向扩展，并标记每个找到的邻居。这个补充建立了完整的不变量：**每个已搜索连续段中的所有数字都在 visited 中，包括启动这次搜索的数字。**

截图中的第二版已通过 85 个测试，但仍缺少起点标记；补全后的线性复杂度由上述不变量保证，本次讨论未提供补全后重新提交的运行时间。

## 6. 为什么 for 里面有 while，仍然可以是 O(n)？

不能仅根据循环嵌套层数把复杂度相乘，要统计所有调用加起来做了多少工作。

设不同数字有 `u` 个，各连续段的长度为 `L1、L2、…、Ls`：

```text
L1 + L2 + … + Ls = u <= n
```

完整标记后，每段只展开一次：起点处理一次，其余数字通过扩展处理一次。每段两端还各有一次失败查询，段数也不超过 `u`。因此：

```text
建立 set：平均 O(n)
外层扫描并判断是否已处理：平均 O(n)
所有双向扩展的总工作量：平均 O(u)
总时间：平均 O(n)
额外空间：O(u)，最坏 O(n)
```

一次内层循环很长没有关系，关键是后面的外层迭代会跳过这一段。这里是在计算整次算法的总成本，而非假设每轮外层都会重复最长的一次搜索。

## 7. 相关方法与取舍

- **只从连续段起点出发**：遍历去重后的集合，只有 `x - 1` 不存在时才从 `x` 向上扩展。每段只有一个起点，因此不需要额外的 visited。外层应遍历集合，避免原数组中重复的起点触发重复搜索。这是同一“每段只处理一次”性质的另一种实现；自己的双向 visited 方法完整标记后同样达到平均 `O(n)`。
- **删除代替标记**：从“尚未处理的数字集合”移除已找到的数字，也能表达处理完成；注意不要一边使用该集合的增强 for 迭代器，一边直接删除元素。
- **并查集**：可以把相邻整数归为同组，维护组内不同数字数量。其 `parent` 数组保存父节点编号，Find 沿父节点找根，Union 连接两个根。本题原始数值很大且可为负，若用数组实现，需要映射到紧凑编号。并查集是可行扩展，并非完成本题的必要前置知识。
- 当前数值范围下 `num ± 1` 不会溢出 Java `int`；如果变种允许完整 int 范围，扩展时需要处理边界，避免溢出后错误连接最大值与最小值。

## 8. 从这次思考中形成的习惯

我的主要障碍是能描述逐个查找，却没有立即发现怎样消除整段重复搜索。可以沿着这条学习链推导：

```text
手动找一段连续整数
→ 发现核心操作是查询相邻值是否存在
→ 用 HashSet 加速查询
→ 发现同一段还在重复搜索
→ 用完整的已处理状态跳过后续起点
→ 用每个数字被处理的总次数证明复杂度
```

与 [[09-454 - 4Sum II]] 的区别：454 保存配对计算的结果，供其他组合反复查询；128 标记已经完成的整段，使后续搜索不再启动。优化既可能是复用已有答案，也可能是证明某些工作可以完全省去。
