# 416. Partition Equal Subset Sum

## 问题

给定一个只包含正整数的数组 `nums`，判断能否把所有元素分成两个子集，使两个子集的元素和相等。

如果数组总和为奇数，不可能平分；如果总和为偶数，问题可以转换为：能否从数组中选择若干个元素，使它们的和等于总和的一半。选出其中一组后，剩余元素自然组成另一组。

## 我的第一反应：回溯

每个元素都有“选择”和“不选择”两种可能，因此可以使用回溯搜索所有子集。实现时通过 `start` 保证每个下标最多使用一次，通过不断减少 `target` 表示距离目标还差多少：

```java
class Solution {
    boolean res = false;

    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int num : nums) {
            sum += num;
        }

        if (sum % 2 == 1) {
            return false;
        }

        backtracking(nums, sum / 2, 0);
        return res;
    }

    void backtracking(int[] nums, int target, int start) {
        if (target == 0) {
            res = true;
            return;
        }

        for (int i = start; i < nums.length; i++) {
            if (res) {
                return;
            }

            if (nums[i] <= target) {
                backtracking(nums, target - nums[i], i + 1);
            }
        }
    }
}
```

这个解法逻辑正确，但提交后超时。最坏情况下，每个元素都要考虑选或不选，搜索规模接近 `2^n`；大量相同数或长数组会产生非常多的组合。

## 为什么会想到 DP

回溯函数中的核心局面由两个信息决定：

- `start`：接下来可以从哪个位置开始选择；
- `target`：距离目标还差多少。

不同的选择路径可能到达相同的 `(start, target)`。一旦这两个值相同，后面可用的元素和剩余目标就完全相同，后续搜索结果也必然相同。普通回溯仍会重复搜索这些局面，这正是超时的核心原因。

因此，这道题从回溯走向 DP 的关键不是换了一套无关的思路，而是把重复出现的状态合并：

```text
回溯：枚举每一条选择路径
记忆化搜索：缓存相同 (start, target) 的结果
DP：按照一定顺序统一计算这些状态
```

## 我的思维误区

- **认为回溯和 DP 是两种没有关系的解法**：回溯已经暴露了状态和选择；DP 是在此基础上合并重复状态。以后遇到回溯超时时，应检查不同路径是否会到达由相同参数描述的局面。
- **最初递归时继续传入 `i`**：这会允许同一个数组元素被重复选择，变成类似完全背包的行为。本题每个下标只能使用一次，因此选中当前元素后，后续搜索必须越过当前下标。
