# Prefix Sum 方法总结：从区间条件到历史前缀查询

> 归类：`01-Array/04-Prefix Sum`。前缀和是一种算法方法，可以用于数组，也能推广到字符串和矩阵。数组总入口：[[Array Problems Summary]]。
> 2026-09-30：新增 523、304 笔记与完整 Java 答案，两题按用户确认记录已完成；525、1524 的原有复盘继续保留。平台通过情况和完成数量以 [[00-Algorithms/99-LeetCode/00-Before/00-Menu|学习菜单]] 为准。

本页重点整理 560、525、1524、523 这类问题的共同解法：**从左到右遍历，固定当前右端点，把区间条件转换为当前前缀与历史前缀的关系，再查询能够匹配的历史信息。** 后面保留 303、304 的区间查询和 238 的前后缀乘积，区分不同的累计用途。

## 1. 先看区间条件，而不是先选 HashMap

看到连续子数组，先问：**如果左右边界已经给定，怎样判断这一段符合条件？需要的是总和、某类元素的数量，还是它们之间的关系？**

如果这些量可以从开头逐步累加，并用两个累计结果相减得到区间信息，就值得考虑前缀和。数量也能累计，所以前缀状态不一定只是原数组元素的总和。

前缀匹配和滑动窗口都可以按右端点从左往右处理。区别在于：本页的方法通过历史前缀同时保留多个候选起点；普通阈值窗口则需要说明，为什么可以安全地把左端点移走。

例如 1524 中 `[1]` 合法、`[1,1]` 不合法、`[1,1,1]` 又合法。在中间那一步丢掉第一个 `1`，会漏掉之后的合法区间。**正数只能保证和随扩张增大，不能保证奇偶性也单调变化。** 560 允许负数时，普通区间和阈值窗口也失去了相应的单调条件。

## 2. 基础公式：一个区间对应两个前缀

统一使用“前缀长度”定义，避免把元素下标和前缀下标混用：

```text
P[k] = 前 k 个元素的累计和
P[0] = 0

区间 [l, r) 包含下标 l 到 r - 1 的元素
区间和 = P[r] - P[l]
区间长度 = r - l
```

如果题目给的是两端都包含的区间 `[left, right]`，就写成：

```text
区间和 = P[right + 1] - P[left]
```

`P[0]` 是空前缀，使从下标 0 开始的区间也能用同一公式。完整前缀数组因此通常开 `n + 1` 个位置。

这里的“相减”适用于和、计数等可加统计。区间最大值不能通过两个前缀最大值相减得到，不能把这条公式机械套给所有区间信息。

## 3. 从两层枚举，变成一次历史查询

前缀和能让一个区间的计算变成 `O(1)`，但如果仍枚举所有 `l、r`，总时间还是 `O(n²)`。下一步优化要问：

> 固定当前右端的前缀长度 r，什么样的历史前缀 l 能与它构成合法区间？

### 560：移项后寻找指定前缀和

```text
P[r] - P[l] = k
P[l] = P[r] - k
```

当前 `P[r]` 已经知道，因此可以直接查询：**过去出现过多少次 `P[r] - k`？** 每个匹配的历史位置都对应一个合法起点。

### 525：等量条件变成相同的数量差

设 `D[k] = 前 k 个元素中 1 的数量 - 0 的数量`：

```text
区间内 1 的数量 - 0 的数量 = D[r] - D[l]
区间内两种数量相等 → D[r] - D[l] = 0 → D[r] = D[l]
```

因此查询相同的数量差。例子：`[1]` 和 `[1,1,0,0,1]` 都是“1 比 0 多一个”，说明中间新增的 `[1,0,0,1]` 中，两种元素一样多。

我最初只统计 `1` 的思路也成立：`2 × 1的数量 - 前缀长度` 正好等于 `1的数量 - 0的数量`。查询 key 来自区间条件的推导；实现时可以直接用两个计数器相减。

### 1524：只需保留前缀和的奇偶性

```text
P[r] - P[l] 是奇数
等价于：P[r] 与 P[l] 的奇偶性不同
```

当前是奇数，就查询历史偶数前缀的个数；当前是偶数，就查询历史奇数前缀的个数。实际数值不同但奇偶性相同的前缀，可以放进同一类统计。

### 523：相同余数之间的区间和是 k 的倍数

```text
(P[r] - P[l]) % k == 0
等价于 P[r] % k == P[l] % k
并且 r - l >= 2
```

查询同余数的最早前缀长度：固定 r 时，l 越早越容易满足长度限制。匹配距离只有 1 时不能返回 true，也不能覆盖最早位置，否则 `[0,0]` 会漏判。空前缀初始化为 `余数 0 → 长度 0`。

这些题都经历同一条推导：

```text
写出区间条件 → 用两个前缀表示 → 确定需要匹配的历史状态
```

## 4. 两个独立的问题：状态是什么，每个状态保存什么？

先决定历史如何分类，再决定每类中哪些信息对答案有用。使用 Map 时，这分别对应 key 和 value：

```text
key：用什么前缀状态区分不同类别？
value：为了回答题目的目标，每个类别需要保留什么信息？
```

| 题目 | 历史状态（key） | 查询的状态 | 每类保存的信息（value） | 为什么 |
| --- | --- | --- | --- | --- |
| 560：和为 k 的子数组数量 | 前缀和 | 当前前缀和减 k | 出现次数 | 每个匹配位置都贡献一个区间 |
| 525：0、1 等量的最长区间 | 1 的数量减 0 的数量 | 当前同一个数量差 | 最早出现时的前缀长度 | 固定右端 r，左侧 l 越早，r - l 越大 |
| 1524：奇数和的子数组数量 | 前缀和的奇偶性 | 相反奇偶 | 出现次数 | 同类中的每个位置都可作为一个起点 |
| 523：长度至少 2、和为 k 的倍数的区间是否存在 | 前缀和除以 k 的余数 | 相同余数 | 最早出现时的前缀长度 | 更早的位置给出更大间隔，必须满足 r-l >= 2 |

**保存次数还是位置，由答案目标决定。** 如果把 525 改为“统计平衡子数组个数”，匹配关系仍然是相同数量差，但 value 应改成次数。求最长时不能覆盖最早位置；求数量时不能只保存“出现过没有”，否则会丢失重复状态对应的不同起点。

## 5. 变量、数组、HashMap：根据状态范围选择容器

我这次的总结是：“只有两类时可以用变量，类别多、分布广时可以用 HashMap。”进一步补全为：**既要看类别数量，也要看取值范围是否适合用数组直接定位。**

| 状态的特点 | 合适的存储方式 | 例子与原因 |
| --- | --- | --- |
| 类别少且固定 | 几个变量，或小数组 | 1524 只有奇、偶两类，两个计数器即可 |
| 整数范围明确，分配空间合理 | 数组 | 26 个小写字母可用 `int[26]`；525 的差在 `[-n,n]` 内，也可以偏移后作为下标 |
| 取值范围大、分布稀疏，或不便事先确定 | HashMap | 前缀和可能只出现少量不同值，但最大最小值相距很远，按实际出现的状态保存更合适 |

### 1524 为什么两个变量就够？

```text
evenCount：历史偶数前缀的出现次数
oddCount：历史奇数前缀的出现次数
```

它们统计的是两类**历史前缀**，不是原数组中有几个偶数元素、几个奇数元素。当前元素的奇偶性影响当前前缀，但匹配对象始终是前缀。

这与 `count[0]、count[1]`，或者 Map 中 `0、1` 两个 key 表示的信息相同。用两个变量表达更直接。也可以由已登记前缀的总数和其中一类的数量推算另一类，但两个计数器通常更清楚。

### HashMap 会影响性能吗？

HashMap 查询和更新通常按平均 `O(1)` 分析，但需要哈希计算、额外存储；Java 的 `HashMap<Integer, Integer>` 还涉及装箱等开销。当状态只有两类时，变量通常更轻量。不过变量和数组也必须能完整表达需要的信息，不能为了少用 Map 而丢失历史位置或次数。

525 若用数组，需把差 `d` 映射到 `d + n`，并区分“未出现”和合法的位置 0；Map 则能直接以差值查询。两种方案的时间均可为 `O(n)`、额外空间均为 `O(n)`，选择时同时考虑范围、实现清晰度和实际性能。

**先推导信息，再选择容器。前缀状态负责把区间变成可匹配的关系，容器负责保存并查询这些状态。**

## 6. 一次遍历的前、中、后：不变量与通用流程

本节用于按右端点逐轮查询历史的解法。准备处理 `arr[i]` 时，历史记录包含 `P[0]..P[i]`；读入当前元素后，形成新的 `P[i+1]`。

```text
初始化空前缀的状态

for 每个元素：
    1. 更新当前前缀状态
    2. 根据区间条件，确定需要匹配的历史状态
    3. 查询历史，用结果更新答案
    4. 把当前前缀登记进历史，供后续位置使用
```

- **处理前**：历史记录只包含更早的前缀，之前右端点的答案已经处理完。
- **处理中**：形成当前前缀，但暂不登记；查询历史得到以当前元素结尾的候选长度或子数组数量。
- **处理后**：登记当前前缀。计数题增加出现次数；525 只在该差第一次出现时保存位置。

每个子数组有唯一右端点，因此按这种方式逐轮计数，只要本轮匹配完整，就不会漏计或重计。

“先查询，再登记”维持了历史只包含更早前缀的统一含义。560 在 `k = 0` 时若先登记，会把当前前缀与自己配对，误计空区间。1524 查询相反奇偶，先登记同奇偶不影响查询值，但保留统一顺序更容易迁移。

### 把流程放进例子：1524 的 `[1,2,3]`

初始 `evenCount = 1、oddCount = 0`，因为空前缀的和为 0。

| 当前元素 | 处理前：偶 / 奇次数 | 处理中：当前前缀和与新增贡献 | 处理后：偶 / 奇次数 | 累计答案 |
| --- | --- | --- | --- | ---: |
| 1 | 1 / 0 | 前缀和 1 为奇数，匹配 1 个偶前缀：`[1]` | 1 / 1 | 1 |
| 2 | 1 / 1 | 前缀和 3 为奇数，匹配 1 个偶前缀：`[1,2]` | 1 / 2 | 2 |
| 3 | 1 / 2 | 前缀和 6 为偶数，匹配 2 个奇前缀：`[2,3]`、`[3]` | 2 / 2 | 4 |

最后一轮减掉前缀 `[1]`，留下 `[2,3]`；减掉前缀 `[1,2]`，留下 `[3]`。因此历史中两个奇前缀会产生两个不同区间。

## 7. 空前缀：初始值由存储含义决定

空前缀是合法起点的表示，不是题目要求统计的非空子数组。它和后面的前缀配对，负责处理从下标 0 开始的区间。

| 场景 | 初始化 | 含义 |
| --- | --- | --- |
| 560，按前缀和计数 | `map.put(0, 1)` | 和为 0 的前缀已经出现一次 |
| 525，保存前缀长度 | `firstSeen.put(0, 0)` | 数量差为 0 的最早前缀，其长度为 0 |
| 1524，按奇偶计数 | `evenCount = 1`，`oddCount = 0` | 空前缀是一个偶数前缀 |
| 523，保存余数的最早位置 | `firstSeen.put(0, 0)` | 余数为 0 的最早前缀，其长度为 0 |

525 的 value 是位置，1524 的 value 是次数，因此不能照抄初始化。以 1524 的 `[1]` 为例，当前前缀为奇数，只有匹配初始偶数前缀，才能把 `[1]` 计入答案。

如果 525 改为保存元素下标，空前缀位置应写成 `-1`；本页统一使用前缀长度，因此写 `0`。定义确定后，求长度和初始化都必须使用同一套下标规则。

## 8. 为什么可以边计算前缀，边处理答案？

我的原写法是先建立整个前缀数组，再按顺序遍历它。这个方案正确，两个顺序执行的循环总时间仍为 `O(n)`。

例如 `[1,2,3]`：

```text
两遍：先算出 [0,1,3,6]，再依次处理 1、3、6
一遍：算出 1 就处理，算出 3 就处理，算出 6 就处理
```

一遍方案的依据是：处理当前右端时，只需要当前前缀状态，以及从历史中保留下来的必要信息。处理次序没有改变，未来前缀也不需要提前知道。

**“先把完整前缀数组算出来”与“先把所有前缀都加入历史查询表”是两回事。** 前者可以作为预处理；后者会破坏这个逐轮解法中“表里只有更早前缀”的不变量，不能直接沿用同一套计数流程。

| 用途 | 需要保留什么 | 空间取舍 |
| --- | --- | --- |
| 303，之后查询任意区间 | 每个位置的具体前缀和 | 完整数组 `O(n)`，预处理后每次查询 `O(1)` |
| 525，寻找最长平衡区间 | 当前数量差、每种差的最早位置 | 可以省掉前缀数组，但位置表仍是 `O(n)` |
| 1524，只统计奇数和区间 | 当前奇偶性、奇偶两类历史次数 | 不必保留完整前缀数组，额外空间 `O(1)` |

“一遍扫描”不自动等于常数空间。也要区分两种数组：`prefix[k]` 按**位置**保存累计结果，`count[state]` 按**状态类别**保存统计量；使用计数数组不代表仍然保存了完整前缀数组。

## 9. 其他前缀用途与题目入口

### 303：已知左右端点，直接查询

输入是固定不变的数组，需要回答多次区间和查询。先花 `O(n)` 时间和空间建立前缀数组，之后每次按 `P[right+1] - P[left]` 查询，耗时 `O(1)`。它不需要额外搜索历史前缀，因为左右边界已经给出。

### 238：前缀与后缀组合，不是区间相减

每个位置需要的是“除了自己之外的所有元素乘积”：

```text
answer[i] = 左侧所有元素的乘积 × 右侧所有元素的乘积
```

从左到右把不包含自己的左侧乘积存入输出数组，再从右到左维护右侧乘积并乘入答案。空侧的乘积为 1。这样无需除法，能处理 0；使用输出数组保存左侧结果，还能省掉单独的左右辅助数组。

它与前缀和共享“复用累计结果”的思想，但不套用“两个前缀相减”的公式。

### 304：二维矩形查询，分别处理两条边与重叠

新建 `(rows+1) × (cols+1)` 的辅助数组，`res[r][c]` 表示原矩阵前 r 行、前 c 列的总和。第 0 行、第 0 列表示空区域，一直为 0；原矩阵不变。

```text
构建：当前元素 + 上方 + 左侧 - 左上重叠
查询：大矩形 - 上方 - 左侧 + 左上重叠
```

构建时重叠被加了两次，查询时重叠被减了两次，所以符号相反。补零使所有边界统一处理；不补零也正确，但访问 `i-1、j-1` 前须判断边界，查询也须使用对应定义。预处理时间与空间均为 `O(rows×cols)`，每次查询 `O(1)`。完整分区图、补零前后的数组和两种写法见单题笔记。

## 10. 本次疑问与实现检查

- **用了前缀和，为什么还担心两个 for？** 单个区间计算快了，不代表枚举区间的数量减少了。省掉起点枚举依靠历史状态查询；两个顺序执行的 for 则本来就是线性时间。
- **类别多就一定要 HashMap 吗？** 还要检查范围。少量固定类别用变量，合理整数范围用数组，范围大且稀疏时考虑 Map。容器不能代替前面的条件推导。
- **Map 总是保存次数吗？** 求数量保存次数；525 求最长保存最早位置。答案目标变化时重新检查 value 的含义。
- **前缀和必须先建数组吗？** 只在后面需要访问具体历史前缀时保留完整数组；能够压缩为位置表或类别次数时，可以边算边处理。
- **初始化和更新是否保持含义一致？** 明确空前缀的位置或次数、当前状态何时登记，检查是否漏掉从开头开始的区间，或误计空区间。
- **数值范围是否安全？** 1524 应在累计过程中取模，不能等 `int` 溢出后才取模；其他题的累计和、区间总数则根据约束判断是否需要 `long`。

复习时试着独立回答：

1. 区间条件怎样写成两个前缀之间的关系？
2. 当前前缀确定后，需要查询哪一类历史状态？
3. 每类应该保存次数、位置，还是其他信息？为什么？
4. 状态范围适合变量、数组还是 Map？
5. 这一轮处理前和处理后，历史记录分别包含哪些前缀？
