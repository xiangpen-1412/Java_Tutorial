# 1524. Number of Sub-arrays With Odd Sum：按右端点统计相反奇偶的历史前缀

> 分类：数组 → 前缀和 / 前缀状态；重点：如何想到，以及每轮处理前、处理中、处理后的含义。
> 配套阅读：[[04-525-Contiguous Array]]、[[02-560-Subarray Sum Equals K]]、[[Prefix Sum Problems Summary]]。

## 问题

给定整数数组 `arr`，统计元素之和为奇数的非空连续子数组数量，最后对 `1_000_000_007` 取模。题目中数组长度最多为 `10^5`，元素范围为 `1..100`。

返回的是子数组的**个数**，不是最长长度。判断的是总和为奇数，不要求每个元素都为奇数；例如 `[1,2]` 的和为 3，也符合条件。相同内容出现在不同位置时，按不同子数组分别计数。

## 核心收获

### 1. 连续子数组为什么没有直接使用滑动窗口？

连续性只说明区间由两个边界决定，还需要判断能否安全移走左端点。

```text
数组：[1,1,1]

[1]       和为奇数，合法
[1,1]     和为偶数，不合法
[1,1,1]   和为奇数，又合法
```

如果在 `[1,1]` 不合法时永久丢弃第一个 `1`，就会漏掉后来的 `[1,1,1]`。即使所有元素都是正数，和的奇偶性仍然会反复变化。

固定最后一个位置为右端点，合法起点也不是一个完整连续范围：`[1,1,1]` 合法、`[1,1]` 不合法、`[1]` 合法。因此不能直接套用“缩到合法后加上窗口长度”的普通阈值窗口。这里需要保留并分类历史起点。

### 2. 先写出区间和，再把要求转换成奇偶关系

定义 `P[k]` 为前 `k` 个元素之和，`P[0] = 0`。区间 `[l, r)` 的和是：

```text
P[r] - P[l]
```

这个差要是奇数，只需两个前缀和的奇偶性不同：

| 当前前缀 `P[r]` | 历史前缀 `P[l]` | 区间和 |
| --- | --- | --- |
| 奇数 | 偶数 | 奇数，合法 |
| 偶数 | 奇数 | 奇数，合法 |
| 奇数 | 奇数 | 偶数，不合法 |
| 偶数 | 偶数 | 偶数，不合法 |

因此固定当前右端点后，问题变成：**在当前前缀之前，有多少个奇偶性相反的前缀？**

每个历史前缀的位置都代表一个不同起点。只要统计匹配前缀的数量，就能一次加入所有以当前元素结尾的合法子数组，无需逐个尝试起点。

### 3. 处理前：历史计数包括谁？

正在准备读取 `arr[i]` 时：

- `parity` 表示前 `i` 个元素之和的奇偶性，也就是 `P[i]` 的奇偶性。
- `evenCount`、`oddCount` 统计已经见过的 `P[0]` 到 `P[i]`，不包括尚未形成的 `P[i+1]`。
- `result` 已经统计完右端点在 `i` 之前的全部合法子数组。

读取第一个元素之前，已经存在一个空前缀 `P[0] = 0`：

```text
parity = 0
evenCount = 1
oddCount = 0
result = 0
```

空前缀本身不算题目要求的子数组。它作为左侧前缀，与后来的 `P[r]` 相减，表示从下标 0 开始的非空区间。

### 4. 处理中：形成当前前缀，用历史计数更新答案

读取 `arr[i]` 后，形成 `P[i+1]`，更新其奇偶性：

```text
parity = (parity + arr[i]) % 2
```

这里只保留余数也足够，因为一个数的奇偶性只由它除以 2 的余数决定。

此时**历史计数仍只包含 `P[0]..P[i]`**：

```text
当前前缀是奇数 → result 加上 evenCount
当前前缀是偶数 → result 加上 oddCount
```

这一次增加的是“以 `arr[i]` 结尾”的合法子数组个数。不同轮次处理不同右端点，所以不会重复计数；每个子数组都有唯一右端点，所以也不会漏计。

### 5. 处理后：把当前前缀登记为下一轮的历史

计算完当前贡献，再更新当前前缀所属的计数：

```text
当前前缀是奇数 → oddCount++
当前前缀是偶数 → evenCount++
```

这样历史范围扩展到 `P[0]..P[i+1]`，下一轮就能继续使用。未来前缀尚未参与当前统计。

这条时间顺序可以写成：

```text
处理前：历史统计准备好
处理中：形成当前前缀 → 查询历史 → 累计当前右端的贡献
处理后：登记当前前缀，供下一轮使用
```

本题查询的是相反奇偶，先增加同奇偶计数并不会改变本轮查询值；但“先查历史、再登记当前”能保持统一的不变量。迁移到 560 等查询相同前缀的场景时，先登记可能误计空区间，不能机械交换顺序。

### 6. 逐轮例子：`arr = [1,2,3]`

完整前缀和是 `[0,1,3,6]`。下表中的“处理前计数”已经包括空前缀：

| 读到的元素 | 处理前计数（偶 / 奇） | 当前前缀和 | 本轮新增子数组 | 累计答案 | 登记后的计数（偶 / 奇） |
| --- | --- | --- | --- | ---: | --- |
| `1` | `1 / 0` | 1，奇数 | 匹配偶前缀 0：`[1]` | 1 | `1 / 1` |
| `2` | `1 / 1` | 3，奇数 | 匹配偶前缀 0：`[1,2]` | 2 | `1 / 2` |
| `3` | `1 / 2` | 6，偶数 | 匹配奇前缀 1、3：`[2,3]`、`[3]` | 4 | `2 / 2` |

最后一轮中，历史奇数前缀出现过两次：减掉前缀 `[1]`，剩下 `[2,3]`；减掉前缀 `[1,2]`，剩下 `[3]`。因此这一轮加的是 2，而不是只加 1。

## 从我的两遍写法，到边计算边处理

我的原思路是：第一遍建立完整的前缀和数组，第二遍按顺序读取前缀，用 Map 统计之前奇偶前缀的次数。**这个思路正确**，修正空前缀初始化和取模后即可使用。

两个 `for` 先后执行，总时间是 `O(n) + O(n) = O(n)`，不是因为出现两个 `for` 就变成 `O(n²)`。

继续观察每一步实际需要的信息：当前前缀只需奇偶性；历史前缀只需偶数有几个、奇数有几个。因此可以分两步减少存储：

1. 奇偶只有两个状态，用两个计数器替代 Map。
2. 算出当前前缀的奇偶性后立即处理，用一个变量替代整个前缀数组。

```text
原写法：先存 [0,1,3,6] → 再依次处理 1、3、6
合并后：算到 1 就处理 → 算到 3 就处理 → 算到 6 就处理
```

处理顺序没有改变，只是不再保存用不到的完整历史值。前缀和是一种累计与相减的思想，不要求一定创建名为 `prefix` 的数组。

若要支持后续任意左右端点的区间查询，完整前缀数组仍有用途；本题只顺序统计一次，可以把空间从 `O(n)` 降到 `O(1)`。

### 保留状态顺序的核心片段

```java
final int MOD = 1_000_000_007;
int evenCount = 1, oddCount = 0;
int parity = 0, result = 0;

for (int num : arr) {
    parity = (parity + num) % 2;       // 形成当前前缀
    if (parity == 1) {
        result = (result + evenCount) % MOD; // 查询历史
        oddCount++;                         // 登记当前
    } else {
        result = (result + oddCount) % MOD;
        evenCount++;
    }
}
```

时间 `O(n)`，额外空间 `O(1)`。在每次加法后取模，使 `result < MOD`；历史计数最多为 `n+1`，在本题范围内，以上单次加法不会使 `int` 溢出。若一直累加到最后才取模，则答案可能先溢出。

## 和 525 放在一起看

| 对比项 | 525：最长平衡区间 | 1524：奇数和区间数量 |
| --- | --- | --- |
| 前缀状态 | 1 的数量减 0 的数量 | 前缀和的奇偶性 |
| 如何匹配 | 找相同的数量差 | 找相反的奇偶性 |
| 保存什么 | 每个差最早出现的位置 | 奇、偶两类各出现多少次 |
| 为什么 | 更早的左侧前缀得到更长区间 | 每个匹配位置都贡献一个区间 |
| 空前缀初始化 | `0 → 0`：差 0，位置为 0 | `0 → 1`：偶数前缀出现 1 次 |

两题初始化不同，是因为 value 的含义不同，不能照抄数字。每次先说清楚“存的是位置，还是次数”。

## 我的思维误区与修正

- **看到连续子数组和正整数，就想用普通滑动窗口**：还要看目标条件能否支持安全排除起点。正数能保证区间和随扩张增大，却不能保证奇偶性单调变化。
- **把偶数前缀次数初始化为 0**：空前缀 `P[0] = 0` 已出现一次。以 `[1]` 为反例，如果没有这个偶数前缀，唯一合法子数组就会漏掉。
- **认为前缀和要先建完整数组，再处理答案**：这种实现合法，但不是必要条件。是否保留数组取决于后面是否需要访问具体历史值；若历史能压缩成次数，就可以边计算边处理。

## 变种与注意点

- 与 1248 的“恰好有 k 个奇数”区分：本题要求总和为奇数，等价于区间内奇数元素的个数为奇数，可以是 1、3、5……，没有指定固定的 k。
- 若条件改成“和能被 k 整除”，两个前缀应具有相同余数；若答案目标再改成最长长度，保存的信息也要从次数改成适当的位置信息。先推导匹配关系，再决定存储含义。
