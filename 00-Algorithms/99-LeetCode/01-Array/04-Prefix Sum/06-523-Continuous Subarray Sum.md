# 523. Continuous Subarray Sum：相同余数与最早位置

> 分类：数组 → 前缀和 / 余数状态；辅助工具：HashMap。
> 配套阅读：[[04-525-Contiguous Array]]、[[05-1524-Number of Sub-arrays With Odd Sum]]、[[Prefix Sum Problems Summary]]。
> 2026-09-30：按本次用户确认记录已完成；以下为标准参考解法，平台提交通过情况未核验。

## 问题

给定非负整数数组 `nums` 和正整数 `k`，判断是否存在一个长度至少为 2、元素之和为 `k` 的倍数的连续子数组。存在返回 `true`，否则返回 `false`。不能跳过元素，整个数组也可以作为子数组；和不必等于 `k`，可以等于 `2k`、`3k`，也可以等于 0，因为 `0 = 0 × k`。

例如 `nums = [23,2,4,6,7]、k = 6`，连续的 `[2,4]` 长度为 2、总和为 6，因此返回 `true`。单独的 `[6]` 即使能整除，也不满足长度要求。

## 核心收获

### 1. 从整除条件转换成相同的前缀余数

定义 `P[t]` 为前 `t` 个元素之和，`P[0] = 0`。区间 `[l,r)` 的和为 `P[r] - P[l]`，长度为 `r - l`。

```text
(P[r] - P[l]) % k == 0
等价于 P[r] % k == P[l] % k

还必须满足 r - l >= 2
```

为什么只比较余数就够？如果 `P[r] = a × k + x`、`P[l] = b × k + x`，相减后余数部分抵消，留下 `(a-b) × k`。因此不同的前缀总和可以归入同一个余数状态，不必保存所有完整前缀和。

前缀和只让一个区间的求和变快；进一步通过 HashMap 查询相同余数，才能省掉逐个尝试起点的循环。整除状态不随区间扩张单调变化，不能直接套普通“超标就缩”的滑动窗口。

### 2. 为什么保存最早位置？

```text
key：前缀和除以 k 的余数
value：该余数第一次出现时的前缀长度
```

固定当前前缀长度 `r`，历史长度 `l` 越小，区间 `r-l` 越长，也越容易满足至少 2 个元素。同余数的新位置不能覆盖最早位置。

反例：`nums = [0,0]`。余数一直为 0；最早位置为 0，读取第二个元素时长度为 `2-0=2`。如果第一轮把位置覆盖为 1，第二轮就只看到长度 1，漏掉合法区间。

初始化 `firstSeen.put(0, 0)`，表示空前缀的余数为 0、前缀长度为 0，用于识别从数组开头开始的合法区间。这里 value 是位置，不是出现次数。

### 3. 用例子跟踪历史查询

`nums = [23,2,4,6,7]、k = 6`：

| 当前前缀 | 前缀长度 | 总和余数 | 处理 |
| --- | ---: | ---: | --- |
| `[]` | 0 | 0 | 初始化 `0 → 0` |
| `[23]` | 1 | 5 | 首次出现，记录 `5 → 1` |
| `[23,2]` | 2 | 1 | 首次出现，记录 `1 → 2` |
| `[23,2,4]` | 3 | 5 | 查到最早长度 1；`3-1=2`，返回 `true` |

最后一次匹配减掉前缀 `[23]`，留下 `[2,4]`。两个前缀本身不必能被 `k` 整除，它们余数相同就足够。

## Java 标准参考代码

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {
        Map<Integer, Integer> firstSeen = new HashMap<>();
        firstSeen.put(0, 0);

        int remainder = 0;
        for (int i = 0; i < nums.length; i++) {
            remainder = (int) (((long) remainder + nums[i]) % k);
            int currentLength = i + 1;
            Integer previousLength = firstSeen.get(remainder);

            if (previousLength != null) {
                if (currentLength - previousLength >= 2) {
                    return true;
                }
            } else {
                firstSeen.put(remainder, currentLength);
            }
        }
        return false;
    }
}
```

用 `long` 做加法再取模，避免中间加法溢出；余数始终小于正整数 `k`，取模后可以转回 `int`。哈希操作按平均常数时间分析，时间为 `O(n)`，额外空间为 `O(min(n,k))`。

## 变种与注意点

- **存在性仍需检查长度**：只用 Set 判断余数出现过，无法知道间隔是否至少为 2；本解法保存最早位置。
- **改为统计子数组数量**：仍匹配相同余数，但通常应保存出现次数；如果仍有长度限制，还需要排除过近的前缀，不能直接照搬所有匹配次数。
- **改为求最长区间**：仍保存最早位置，每轮更新最大长度，而不是找到一个就返回。
- **允许负数**：Java 的 `%` 可能得到负数，应把余数统一到 `[0,k)`，例如在安全的数值类型中使用 `((sum % k) + k) % k`。
- **本题 `k >= 1`**：不需要处理除零；若变种允许 `k = 0`，须单独按区间和为 0 判断，不能继续 `% k`。
- **位置定义不要混用**：这里保存前缀长度，空前缀位置为 0；若保存元素下标，空前缀位置才是 `-1`。
