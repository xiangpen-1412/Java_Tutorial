# 525. Contiguous Array：用相同的前缀数量差寻找最长区间

> 分类：数组 → 前缀和 / 前缀状态；辅助工具：HashMap。
> 配套阅读：[[05-1524-Number of Sub-arrays With Odd Sum]]、[[Prefix Sum Problems Summary]]。

## 问题

给定只包含 `0` 和 `1` 的数组 `nums`，返回其中 `0` 和 `1` 数量相等的最长连续子数组的长度。元素必须连续，但不要求交替出现，例如 `[0,0,1,1]` 也符合条件。没有合法区间时返回 `0`。数组长度最多为 `10^5`，不能枚举所有左右端点。

## 核心收获

### 1. 从哪里想到前缀和？

题目要判断“一段区间里两种元素各有多少个”。数量可以累加，也可以通过两个前缀的数量相减得到，因此适合考虑前缀统计。

先问：如果已经知道区间的左右边界，怎样判断它是否符合条件？答案是比较区间内 `0` 和 `1` 的数量。再问：怎样复用不同区间重叠的统计？这就引出前缀和。

但前缀和只让单个区间的判断变成 `O(1)`。如果仍然用两层循环尝试所有起点和终点，总时间还是 `O(n²)`。还需要把“尝试所有起点”转成“查询历史前缀”。

### 2. 保留我最初的思路：只数 1，再通过位置算长度

统一定义 `P[k]` 为**前 k 个元素中 1 的数量**，`P[0] = 0`。这里 `k` 是元素个数；例如前 3 个元素对应下标 `0、1、2`。

对区间 `[l, r)`，也就是下标 `l` 到 `r - 1`：

```text
区间长度 = r - l
区间里 1 的数量 = P[r] - P[l]
区间里 0 的数量 = (r - l) - (P[r] - P[l])
```

两种数量相等，等价于：

```text
2 × (P[r] - P[l]) = r - l

移项后：
2 × P[r] - r = 2 × P[l] - l
```

固定右端的前缀长度 `r`，右边不再需要挨个试 `l`，而是可以查询：之前哪个前缀也有相同的 `2 × P[k] - k`？

这个表达式不是凭空设计的。因为前缀长度等于两种数量之和：

```text
2 × 1的数量 - 前缀长度
= 2 × 1的数量 - (1的数量 + 0的数量)
= 1的数量 - 0的数量
```

因此，实现时直接分别维护 `countOne`、`countZero` 更直观，查询的 key 就是 `countOne - countZero`。

### 3. 为什么两个前缀的数量差相同，中间就平衡？

用本次讨论的数组：

```text
nums = [1, 1, 0, 0, 1]

之前：[1]                 1 个 1，0 个 0，差为 1
现在：[1 | 1, 0, 0, 1]    3 个 1，2 个 0，差为 1
```

从“之前”走到“现在”，`1` 增加了 2 个，`0` 也增加了 2 个。**前后的数量差没变，说明中间新增的两种元素一样多。** 中间部分 `[1,0,0,1]` 的长度是 `5 - 1 = 4`。

不要求这两个前缀各自平衡：上面两个前缀的差都为 `1`，都不平衡；但它们之间的区间平衡。只判断当前整个前缀的差是否为 `0`，会漏掉从中间开始的合法区间。

### 4. Map 为什么保存最早位置？

Map 的含义是：

```text
数量差 → 第一次出现这个差时的前缀长度
```

当前前缀长度为 `r`，查到更早的长度 `l`，就得到候选长度 `r - l`。固定 `r` 时，`l` 越小，区间越长，所以同一个差只保存最早位置，不能覆盖成最近位置。

开始时放入 `0 → 0`：空前缀的数量差为 `0`，它的长度为 `0`。注意 value 是**位置（前缀长度）**，不是出现次数。

完整过程如下，每一行处理当前右端点：

| 已读前缀 | 前缀长度 | 数量差 | 查询与处理 | 当前最大长度 |
| --- | ---: | ---: | --- | ---: |
| `[]` | 0 | 0 | 初始记录 `0 → 0` | 0 |
| `[1]` | 1 | 1 | 首次出现，记录 `1 → 1` | 0 |
| `[1,1]` | 2 | 2 | 首次出现，记录 `2 → 2` | 0 |
| `[1,1,0]` | 3 | 1 | 查到最早长度 1，候选为 `3 - 1 = 2`；不覆盖旧记录 | 2 |
| `[1,1,0,0]` | 4 | 0 | 查到最早长度 0，候选为 `4 - 0 = 4` | 4 |
| `[1,1,0,0,1]` | 5 | 1 | 仍查到最早长度 1，候选为 `5 - 1 = 4` | 4 |

## Java 答案代码

下面采用本次更容易理解的“双计数器”写法。Map 中始终保存前缀长度，因此差值直接相减得到区间长度，不混用元素下标。

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int findMaxLength(int[] nums) {
        // 数量差 → 最早出现时的前缀长度
        Map<Integer, Integer> firstSeen = new HashMap<>();
        firstSeen.put(0, 0);

        int countZero = 0;
        int countOne = 0;
        int maxLength = 0;

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == 0) {
                countZero++;
            } else {
                countOne++;
            }

            int difference = countOne - countZero;
            int currentLength = i + 1;
            Integer previousLength = firstSeen.get(difference);

            if (previousLength != null) {
                int length = currentLength - previousLength;
                maxLength = Math.max(maxLength, length);
            } else {
                firstSeen.put(difference, currentLength);
            }
        }

        return maxLength;
    }
}
```

在哈希操作平均为常数时间的通常分析下，总时间为 `O(n)`，额外空间为 `O(n)`。只有一层遍历；历史起点的搜索由 Map 查询完成。

## 变种与注意点

- **求最长改为统计数量**：仍匹配相同数量差，但需要记录每个差出现过多少次，并把匹配次数加入答案；最早位置只能提供最长长度，不能提供所有起点的数量。
- **用元素下标存位置也可以**：那时空前缀的位置是 `-1`，初始化应为 `0 → -1`。本篇统一用前缀长度，因此初始化是 `0 → 0`，不要混用两种定义。
- **HashMap 是工具，前缀状态是方法**：这题归入数组下的前缀和专题；并不是看到 Map 就必须归到哈希专题。

## 我的思维误区与修正

- **以为用了前缀和就仍要两层遍历，因此一定很慢**：保留两层枚举确实是 `O(n²)`；优化来自把区间条件整理成前缀之间的匹配关系，再查询历史信息。前缀和与哈希查询分别解决不同的重复工作。
- **能通过 1 的数量和长度判断平衡，却不知道怎样找区间**：判断单个区间只是第一步。写出区间条件，再把当前前缀与历史前缀的项分到两边，才能知道 Map 应查询什么 key。
- **直接看到 `2 × ones - length` 很难理解**：先还原成“1 的数量减 0 的数量”，再用两个前缀之间新增的元素解释相等条件。公式是计数关系的简写。
