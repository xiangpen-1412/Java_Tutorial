# 304. Range Sum Query 2D - Immutable：矩形前缀和与重叠区域

## 问题

给定一个不会修改的整数矩阵 `matrix`，实现 `NumMatrix` 类，支持多次调用 `sumRegion(row1,col1,row2,col2)`，返回左上角 `(row1,col1)` 到右下角 `(row2,col2)` 的矩形内所有元素之和，包含两端边界。行、列下标从 0 开始，坐标先写行，再写列。题目要求每次查询为 `O(1)`，可以在构造对象时预处理。

例如以下矩阵中，`sumRegion(2,1,4,3)` 查询第 2～4 行、第 1～3 列：

```text
matrix                         查询区域
3  0  1  4  2
5  6  3  2  1
1  2  0  1  5                 2  0  1
4  1  0  1  7                 1  0  1
1  0  3  0  5                 0  3  0

结果 = 3 + 2 + 3 = 8
```

## 核心收获

### 1. 为什么不只存整行和整列？

整行、整列的总和会带入目标之外的边缘，而且没有单独保存这些边缘区域，不能直接恢复任意矩形。若保存每行的一维前缀和，可以逐行算出指定列区间，再累加，结果正确，但每次查询仍需要 `O(查询行数)`，达不到本题要求。

二维前缀和改为保存：**从矩阵左上角到每个位置的整个矩形之和**。这样上方、左侧以及它们的重叠部分都能直接查询。

### 2. 先画图理解为什么要加回重叠

暂时用不补零的 `P[r][c]` 表示从 `(0,0)` 到 `(r,c)` 的和。对于查询 `(2,1)` 到 `(4,3)`，把大矩形分成四块：

```text
              第 0 列       第 1～3 列
            ┌──────────┬──────────────┐
第 0～1 行  │ A：重叠  │ B：上方      │
            ├──────────┼──────────────┤
第 2～4 行  │ C：左侧  │ D：目标      │
            └──────────┴──────────────┘

大矩形 P[4][3] = A + B + C + D
上方   P[1][3] = A + B
左侧   P[4][0] = A + C
重叠   P[1][0] = A
```

```text
大矩形 - 上方 - 左侧
= (A+B+C+D) - (A+B) - (A+C)
= D-A

目标 D = 大矩形 - 上方 - 左侧 + 重叠
```

**A 原来只有一份，却被减了两次，所以加回一份。** 用上面的矩阵核对：`38-24-14+8=8`。不能直接减 `P[2][1]`，因为第 2 行和第 1 列属于目标，应该减掉它们之前的区域。

### 3. 多留一行、一列后，数组具体长什么样？

标准实现新建 `res = new int[rows+1][cols+1]`，原矩阵不变。Java 的 `int` 数组默认填 0，不需要手动填零。

```text
原矩阵 matrix（2×2）     新建 res（3×3）       算完的 res（3×3）

     列0 列1                 列0 列1 列2           列0 列1 列2
行0   1   2             行0    0   0   0       行0    0   0   0
行1   3   4             行1    0   0   0       行1    0   1   3
                        行2    0   0   0       行2    0   4  10
```

额外的第 0 行、第 0 列一直为 0，表示空区域；右下部分保存累计和，不是把原来的数字原样复制过去。例如 `res[2][2]=1+2+3+4=10`。

统一定义：

```text
res[r][c] = 原矩阵前 r 行、前 c 列的总和
          = 行 [0,r)、列 [0,c) 的矩形之和

原矩阵从 (0,0) 到 (i,j) 的和，存到 res[i+1][j+1]
```

多留的位置属于新建的辅助数组；原矩阵的下标仍然从 `(0,0)` 开始。

### 4. 构建与查询：重叠的符号不同

构建时，上方和左侧都已经包含左上角，所以应减掉重复的一份：

```text
res[i+1][j+1] = matrix[i][j]
              + res[i][j+1]       上方
              + res[i+1][j]       左侧
              - res[i][j]         左上重叠
```

查询时，扣掉上方与左侧后，重叠部分被多扣了一份，所以应加回：

```text
答案 = res[row2+1][col2+1]     大矩形
     - res[row1][col2+1]       上方
     - res[row2+1][col1]       左侧
     + res[row1][col1]         左上重叠
```

当 `i=0、j=0` 时，构建式为 `res[1][1]=matrix[0][0]+res[0][1]+res[1][0]-res[0][0]`，全部下标都合法，三个边界项都是 0。查询从第 0 行或第 0 列开始时，同样自动减去空区域。

## Java 标准答案

```java
class NumMatrix {
    private final int[][] res;

    public NumMatrix(int[][] matrix) {
        int rows = matrix.length;
        int cols = matrix[0].length;
        res = new int[rows + 1][cols + 1];

        for (int i = 0; i < rows; i++) {
            for (int j = 0; j < cols; j++) {
                res[i + 1][j + 1] = matrix[i][j]
                        + res[i][j + 1]
                        + res[i + 1][j]
                        - res[i][j];
            }
        }
    }

    public int sumRegion(int row1, int col1, int row2, int col2) {
        return res[row2 + 1][col2 + 1]
                - res[row1][col2 + 1]
                - res[row2 + 1][col1]
                + res[row1][col1];
    }
}
```

预处理时间 `O(rows × cols)`，额外空间 `O(rows × cols)`，每次查询 `O(1)`。按本题矩阵大小和元素范围，`int` 足够；若变种允许更大的累计和，辅助数组应改为 `long[][]` 并检查返回类型。

## 不补零也可以，但必须判断边界

自己的原式 `res[i][j]=res[i-1][j]+res[i][j-1]+matrix[i][j]-res[i-1][j-1]` 在 `i=0` 或 `j=0` 时会访问 `-1`。若希望 `res` 与原矩阵同样大小，可保留直接对应关系，但写成：

```java
res[i][j] = matrix[i][j];
if (i > 0) {
    res[i][j] += res[i - 1][j];
}
if (j > 0) {
    res[i][j] += res[i][j - 1];
}
if (i > 0 && j > 0) {
    res[i][j] -= res[i - 1][j - 1];
}
```

对应查询应从 `res[row2][col2]` 开始，`row1>0` 才减 `res[row1-1][col2]`，`col1>0` 才减 `res[row2][col1-1]`，两者都大于 0 才加 `res[row1-1][col1-1]`。复杂度相同，但构建和查询都增加了边界判断。

## 我的思维误区与修正

- **分别算行与列后，发现边缘成了多个未知量**：问题不在于再解几个变量，而在于存储信息不足。保存左上角矩形后，上方、左侧和重叠都是可直接查询的已知区域。
- **直接用右下角前缀减左上角前缀**：二维目标不是一个大矩形扣掉一个左上矩形；还要分别扣掉上方和左侧，并补偿重叠。先分 A、B、C、D，再写公式。
- **把补零理解成改变原矩阵，或觉得 `+1` 产生歧义**：补零只发生在辅助数组中。先定义 `res[r][c]` 为前 r 行、前 c 列的和，`+1` 就是在把原矩阵元素下标转换成行、列数量。
- **发现 `i-1、j-1` 越界后，不确定如何处理**：不补零加边界判断，或补零后整体平移辅助数组下标，两种写法都正确。不能用一种方式构建，再套另一种方式查询。

## 变种与注意点

- 若矩阵需要修改，已有前缀和会失效；频繁更新与查询时应考虑二维树状数组等结构，不能直接沿用静态预处理。
- 若每个位置都查询周围固定半径的块，可复用矩形查询，但先把边界裁剪到矩阵内。
- `int[][]` 根据行、列下标存值；HashMap 根据 key 查 value。二维前缀和用数组存储，因为行列范围固定且需要直接按坐标访问。
