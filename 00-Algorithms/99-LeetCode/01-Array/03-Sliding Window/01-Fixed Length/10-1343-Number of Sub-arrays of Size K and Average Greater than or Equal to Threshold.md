# 1343. Number of Sub-arrays of Size K and Average Greater than or Equal to Threshold

## 问题

给定整数数组 `arr`、窗口长度 `k` 和整数 `threshold`，统计有多少个**长度恰好为 `k`、平均值大于等于 `threshold` 的连续子数组**。返回的是符合条件的窗口数量；不同位置的窗口即使内容相同，也分别计数。

题目范围：`1 <= k <= arr.length <= 10^5`，`1 <= arr[i] <= 10^4`，`0 <= threshold <= 10^4`。

## 核心收获

### 连续 + 长度固定 → 定长滑动窗口

相邻窗口重叠了 `k - 1` 个元素，只需减去离开的元素，再加上新进入的元素，就能复用原来的总和。你这次的代码已经正确使用了这个方法：先建好第一个窗口，判断一次，再逐个向右滑动。

令 `right` 表示新加入元素的下标：

```text
更新前：sum = arr[right - k ... right - 1] 的和
移出：  arr[right - k]
加入：  arr[right]
更新后：sum = arr[right - k + 1 ... right] 的和
```

**每次判断时，`sum` 都必须对应一个完整的、长度为 `k` 的窗口。** 因此判断应放在移出、加入都完成之后，不能在中间长度为 `k - 1` 的状态下统计。

### 平均值达标 → 总和达标

所有窗口的长度都是正整数 `k`，所以数学上：

```text
sum / k >= threshold
等价于
sum >= k * threshold
```

你用 `thresum = k * threshold` 预先计算总和门槛，这个转换是正确的。它避免了反复计算平均值，也让比较始终在整数范围内完成。等于门槛也符合要求，所以必须使用 `>=`。

和 [[09-643-Maximum Average Subarray I]] 对比：

| 题目 | 窗口维护的状态 | 如何更新答案 |
| --- | --- | --- |
| 643：最大平均值 | 当前窗口和 `sum` | 更新 `maxSum`，最后转成浮点数除以 `k` |
| 1343：达标窗口数量 | 当前窗口和 `sum` | 每个窗口满足 `sum >= k * threshold` 就计数一次 |

两道题的窗口移动方式完全相同，变化的是**如何利用当前窗口更新答案**。

### 第一个窗口单独统计，后续每次移动统计一次

你的结构可以概括为下面这一小段。进入代码片段前，`sum` 已是 `arr[0 ... k - 1]` 的总和：

```java
int targetSum = k * threshold;
int res = sum >= targetSum ? 1 : 0;

for (int right = k; right < arr.length; right++) {
    sum -= arr[right - k];
    sum += arr[right];
    if (sum >= targetSum) {
        res++;
    }
}
```

数组长度为 `n` 时，合法窗口的起点是 `0 ... n - k`，共 `n - k + 1` 个。初始化统计第一个窗口，循环再检查 `n - k` 个窗口，刚好覆盖全部窗口，不漏算也不重复。

## 例子：逐个窗口计数

`arr = [2, 2, 2, 2, 5, 5, 5, 8]`，`k = 3`，`threshold = 4`，总和门槛是 `12`。

| 窗口下标 | 窗口内容 | 总和 | 达标？ |
| --- | --- | ---: | --- |
| `[0, 2]` | `[2, 2, 2]` | 6 | 否 |
| `[1, 3]` | `[2, 2, 2]` | 6 | 否 |
| `[2, 4]` | `[2, 2, 5]` | 9 | 否 |
| `[3, 5]` | `[2, 5, 5]` | 12 | 是，等于门槛也算 |
| `[4, 6]` | `[5, 5, 5]` | 15 | 是 |
| `[5, 7]` | `[5, 5, 8]` | 18 | 是 |

答案是 `3`。即使某个窗口不达标，也照常向右滑动一格；不能通过缩短窗口来让它达标，因为题目要求长度恰好为 `k`。

## 变种与注意点

- **边界**：`k = 1` 时逐个统计达标元素；`k = n` 时只有初始化的一个窗口，后面的循环不执行；`threshold = 0` 时，由于本题元素均为正数，全部 `n - k + 1` 个窗口都达标。
- **复杂度**：初始化花 `O(k)`，其余 `n - k` 个窗口各花 `O(1)`，合计 **`O(n)` 时间、`O(1)` 额外空间**。如果每个窗口都重新累加，则要花 `O((n - k + 1)k)`。
- **整数范围**：本题 `sum` 和 `k * threshold` 最大都不超过 `10^9`，`int` 足够。范围扩大时应改用 `long sum` 和 `long targetSum = 1L * k * threshold`，保证乘法本身就在 `long` 下进行。
- **除法要结合条件判断**：本题的 `sum` 非负、`threshold` 为整数，因此 Java 的 `sum / k >= threshold` 也能正确判断；你的乘法写法更直接。但不能据此认为整数除法能用于所有平均值题：643 要返回实际平均值，仍必须保留小数。
- **条件变化时重新分析**：固定长度下，即使元素允许负数，移出、加入的更新式和乘法比较仍成立。若窗口长度可以变化，门槛也会随长度变化，不能继续固定使用 `k * threshold`，更不能直接假设收缩窗口就能恢复合法。
