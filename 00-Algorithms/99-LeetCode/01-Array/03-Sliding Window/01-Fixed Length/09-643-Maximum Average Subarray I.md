# 643. Maximum Average Subarray I

## 问题

给定整数数组 `nums` 和正整数 `k`，找出所有**长度恰好为 `k` 的连续子数组**中最大的平均值，返回这个平均值。这里不能任意挑选 `k` 个元素，也不能改变窗口长度。题目范围为 `1 <= k <= nums.length <= 10^5`，元素可以为负数，且绝对值不超过 `10^4`。[题目链接](https://leetcode.com/problems/maximum-average-subarray-i/description/)

## 核心收获

### 连续 + 固定长度 → 固定长度滑动窗口

相邻两个候选窗口重叠了 `k - 1` 个元素。窗口向右移动一格时，只会移出一个元素、加入一个元素，因此不需要重新求出整个窗口的和：

```text
新窗口总和 = 旧窗口总和 - 移出的元素 + 新加入的元素
```

例如 `nums = [1, 12, -5, -6, 50, 3]`、`k = 4`：

| 窗口下标 | 窗口内容 | 总和的更新 | 总和 |
| --- | --- | --- | ---: |
| `[0, 3]` | `[1, 12, -5, -6]` | 第一次完整求和 | 2 |
| `[1, 4]` | `[12, -5, -6, 50]` | `2 - 1 + 50` | 51 |
| `[2, 5]` | `[-5, -6, 50, 3]` | `51 - 12 + 3` | 42 |

最大平均值为 `51 / 4 = 12.75`。复用的是相邻窗口中的重叠部分，无论里面的数是正数还是负数，更新等式都成立。

### 维护不变量：`sum` 必须对应当前完整窗口

先计算第一个窗口 `nums[0 ... k - 1]` 的总和。后续令 `right` 表示**这次新加入的元素下标**，则：

```text
更新前：sum 对应 nums[right - k ... right - 1]
移出：  nums[right - k]
加入：  nums[right]
更新后：sum 对应 nums[right - k + 1 ... right]
```

下标不能只按变量名猜；要先写清“更新前 `sum` 对应哪个区间”，再确定离开的元素。

### 固定分母 → 先比较总和，最后只除一次

每个窗口的长度都是同一个正数 `k`，因此总和越大，平均值也越大。只维护 `maxSum`，最后转成浮点数除以 `k` 即可：

```java
// sum 已经是第一个长度为 k 的窗口总和
int maxSum = sum;

for (int right = k; right < nums.length; right++) {
    sum -= nums[right - k];
    sum += nums[right];
    maxSum = Math.max(maxSum, sum);
}

return (double) maxSum / k;
```

这样省去了每个窗口的浮点除法，也不需要单独维护 `left`，或在循环内部反复判断是否为第一个窗口。

### 为什么已经是最优的时间复杂度

第一个窗口花 `O(k)` 求和，其余 `n - k` 次移动每次只花 `O(1)`，合计 **`O(n)` 时间、`O(1)` 额外空间**。每个窗口重新求和则需要 `O((n-k+1)k)`。

最坏情况下，任何一个元素都可能影响最大平均值，必须检查全部元素，因此一般不能比 `O(n)` 更低。减少除法和分支可以减少实际开销，但不会改变复杂度。

## 变种与注意点

- **全负数也必须选一个窗口**：`maxSum` 应来自第一个实际窗口，不能默认从 `0` 开始；否则可能返回一个并不存在的非负答案。`k = 1` 时等价于找最大元素，`k = n` 时只计算整个数组一次。
- **固定窗口与可变窗口不同**：本题每次固定移出一个、加入一个，长度始终为 `k`。[[03-3-Longest Substring Without Repeating Characters]] 则根据重复情况持续收缩左端，窗口长度会改变。本题允许负数仍可直接滑动；不能因此推断“含负数的区间和条件”也一定能靠扩张、收缩来恢复合法。
- **分母变化时不能只比较总和**：若改成不同长度的窗口，较大的总和不一定意味着较大的平均值，必须重新分析目标和约束。
- **累加类型由范围决定**：本题窗口和的绝对值至多为 `10^9`，`int` 足够。若元素范围或窗口长度增大，要检查是否需要 `long`。

## 我的思维误区

### 左指针已经前进，却仍用它移出旧元素

我的原代码在每轮结尾执行了 `left++`、`right++`，下一轮再执行 `sum -= nums[left]`。但此时 `left` 已经指向**新窗口左端**，该元素仍应保留。

沿用上面的例子，窗口从 `[0, 3]` 变成 `[1, 4]` 时，新一轮 `left = 1`、`right = 4`。应移出的是旧下标 `0`，而不是新左端下标 `1`：

```java
// 保留原先“在上轮末尾移动左右指针”的结构
sum -= nums[left - 1];
sum += nums[right];
```

更容易复用的判断是：**先确定旧窗口和新窗口的差别，再写移入、移出的下标。** 只维护新加入下标 `right` 时，移出位置就是 `right - k`。

### 以为在整数除法外面加 `(double)` 就能保留小数

我的两处平均值计算都写成了 `(double) (sum / k)`，整数除法已经先丢掉小数，之后转换无法恢复。应在除法前转换一个操作数：`(double) sum / k`。完整的 Java 类型与除法规则见 [[10-Integer Division & Double Keys]]。
