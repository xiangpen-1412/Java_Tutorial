# 1358. Number of Substrings Containing All Three Characters

## 问题

给定只包含 `a、b、c` 的字符串 `s`，统计有多少个连续子串包含这三种字符，且每种至少出现一次。允许重复，例如 `abca` 仍然符合条件；不要求长度为 3，也不要求每种字符只出现一次。不同起止位置分别计数。`3 <= s.length <= 50000`。

例如 `s = "abca"`，符合条件的是 `abc、bca、abca`，答案为 `3`。

## 核心收获

### 同一道题可以选择不同的辅助统计目标

原题只会出现三种字符，因此以下说法等价：

```text
包含 a、b、c，每种至少一次
⇔ 恰好包含 3 种不同字符

答案 = atMostKinds(3) - atMostKinds(2)
     = 全部非空子串数量 - 最多两种字符的子串数量
```

这里连接了第四层的覆盖计数和第五层的“恰好 K”：`K` 是字符种类数，固定为 `3`。因为任何子串都不可能超过三种字符，`atMostKinds(3)` 可以直接算为 `n * (n + 1) / 2`。它是 [[22-992-Subarrays with K Different Integers]] 的字符版本。

### 我采用的写法：统计“最多两种”，超标时收缩

`count[0..2]` 始终记录当前闭区间 `[left, right]` 里三种字符的次数。辅助目标是“最多两种”，所以三种字符都出现时，辅助窗口就超标了：

```java
// 加入当前 right 后
while (count[0] > 0 && count[1] > 0 && count[2] > 0) {
    count[s.charAt(left) - 'a']--;
    left++;
}
atMostTwo += right - left + 1;
```

退出 `while` 后，窗口至少缺少一种字符，且其中任何后缀也不可能增加种类数。因此，固定当前 `right`，起点 `left ... right` 都满足辅助条件；这一步统计的是这些起点，不是窗口内部所有子串。

更早的起点已在包含三种字符时被移除，右端继续扩张也不会丢失已有字符，所以它们不会重新变成“最多两种”，不必回头。

以 `abca` 为例：

| right | 收缩后的辅助窗口 | 本轮计入的子串 | 新增数量 |
| --- | --- | --- | ---: |
| 0 | `a` | `a` | 1 |
| 1 | `ab` | `ab、b` | 2 |
| 2 | `bc` | `bc、c` | 2 |
| 3 | `ca` | `ca、a` | 2 |

最多两种的数量为 `7`，全部非空子串为 `10`，原题答案为 `10 - 7 = 3`。如果直接返回辅助计数，回答的是“没有凑齐三种字符的子串数量”。

### 另一种正确计数：凑齐后，统计完一个起点的所有终点

若 `[left, right]` 已经包含三种字符，那么固定 `left`，右端取 `right ... n - 1` 都合法。因此可以先加 `n - right`，再移除左端；如果仍凑齐，就继续处理下一个起点。

例如 `abcabc`，`left = 0、right = 2` 时，一次计入 `abc、abca、abcab、abcabc` 共 4 个。这个起点的所有合法终点已经计完，所以可以永久移走 `left = 0`，不会漏掉未来追加字符的答案。后续起点分别贡献 `3、2、1`，总计 `10`。

这套 `while` 在原题合法时计数并收缩，退出时反而不再包含三种字符；辅助计数法则在辅助条件超标时收缩，退出时满足“最多两种”。不能脱离统计目标只比较两个 `while` 的外观。

## 变种与注意点

- **总数公式和中间溢出**：非空子串总数是 `1 + 2 + ... + n = n(n+1)/2`，不是 `n(n-1)`。本题 `n = 50000` 时，除法前的乘积为 `2,500,050,000`，超过 `int`，即使最终总数仍能放入 `int`。Java 可写 `(int) ((long) n * (n + 1) / 2 - atMostTwo)`，必须在乘法前提升类型。
- **字符范围是等价转换的前提**：若允许出现 `d` 等其他字符，“恰好三种”可能是 `a、b、d`，不再等价于包含 `a、b、c`；补集仍能定义，但不能直接用“最多两种”代替。
- **两种方法都是 O(n) 时间、O(1) 额外空间**：左右指针各自只前进，字符计数只有三项。批量计入未来终点并不需要真的遍历它们。

## 我的思维误区

- **认为 left 只能在原题条件不满足时移动**：缺少某个字符时，缩小窗口确实补不出缺失字符。要用熟悉的“超标时收缩”，必须先把辅助目标定义为“最多两种”；若直接做原题，则在已统计完当前起点全部合法终点后移动 left。
- **认为 `right - left + 1` 是整个窗口内部所有子串的数量**：长度为 3 的窗口共有 6 个非空子串，但当前轮次只计以 right 结尾的 3 个，避免把早已结束的子串重复统计。
- **把补集与“恰好 K”看成两套无关方法**：本题的 `总数 - atMostKinds(2)`，正是 `atMostKinds(3) - atMostKinds(2)` 的简化。
