# 2962. Count Subarrays Where Max Element Appears at Least K Times

## 问题

给定整数数组 `nums` 和正整数 `k`，统计有多少个连续子数组，其中**整个 nums 的最大值**出现至少 `k` 次。最大值先在整个数组中确定，之后只统计这个固定值；不是分别寻找每个窗口自己的最大值。`1 <= nums.length <= 100000`，答案可能超过 `int`。

例如 `nums = [1,3,2,3,3]、k = 2`，全局最大值为 `3`。合法子数组为 `[1,3,2,3]、[1,3,2,3,3]、[3,2,3]、[3,2,3,3]、[2,3,3]、[3,3]`，答案是 `6`。另如 `nums = [2,2,3]、k = 2`，子数组 `[2,2]` 虽然自身最大值重复两次，却没有包含两次全局最大值 `3`，因此不合法，整个例子的答案为 `0`。

## 核心收获

### 固定全局最大值后，窗口只需维护出现次数

先遍历一次得到最大值 `max`。窗口加入或移出的元素等于 `max` 时才改变计数，其他元素的大小和数量不影响条件。

### “至少”允许把一个起点的未来答案一起计入

当 `[left, right]` 已含至少 `k` 个 `max`，继续向右延伸只会维持或增加出现次数，所以固定 `left`，终点 `right ... n - 1` 全部合法。

```java
while (maxCount >= k) {
    answer += n - right;
    if (nums[left] == max) maxCount--;
    left++;
}
```

移动 left 的理由是：这个起点的所有合法终点已经计完。不是因为这个起点“不合法”。每个起点只处理一次，计数后就移走，避免后续 right 再次计入它。

在例子中，`right = 3` 时：

| 当前起点 | 最早合法窗口 | 可选终点 | 贡献 |
| ---: | --- | --- | ---: |
| 0 | `[1,3,2,3]` | 3、4 | 2 |
| 1 | `[3,2,3]` | 3、4 | 2 |

收缩后不足两个 `3`，继续扩大右端。`right = 4` 时，起点 `2、3` 分别再贡献 1，总数为 `2 + 2 + 1 + 1 = 6`。

### 为什么是 n - right，不再加 1

`right` 是从零开始、包含在窗口内的下标。最后一个可选终点是 `n - 1`：

```text
终点数量 = (n - 1) - right + 1 = n - right
```

例如 `n = 5、right = 3`，可选终点只有 `3、4`，数量为 `2`。这里固定的是左端点；`right - left + 1` 则是在另一类窗口中固定右端点、统计合法起点，不能混用。

## 变种与注意点

- **也可以做补集**：答案等于全部子数组数量减去“全局最大值最多出现 `k - 1` 次”的数量。后者采用超标时收缩，再加窗口长度的方式；参见 [[18-1358-Number of Substrings Containing All Three Characters]]。
- **若改成恰好出现 k 次**：未来加入一个 `max` 可能破坏条件，不能照搬 `n - right`。可以用“至多 k 次减至多 k - 1 次”，参见 [[20-930-Binary Subarrays With Sum]] 的范围计数推导。
- **答案用 long**：当 `n = 100000`、所有元素相同且 `k = 1`，答案为 `5,000,050,000`。若用总数公式，应在乘法前写 `(long) n`。
- 总共扫描和移动指针的工作量为 `O(n)`，额外空间为 `O(1)`；若整个数组中的最大值不足 `k` 次，答案自然为 `0`。

## 我的思维误区

- **在 `n - right` 后再加一**：把数组长度 n 当成了最后一个下标。下次先写出可选终点的闭区间 `[right, n - 1]`，再用“末端减起点加一”计算。

本轮讨论了题意、全局最大值与计数边界，没有记录独立完整实现；不把理解过公式等同于已经熟练迁移。
