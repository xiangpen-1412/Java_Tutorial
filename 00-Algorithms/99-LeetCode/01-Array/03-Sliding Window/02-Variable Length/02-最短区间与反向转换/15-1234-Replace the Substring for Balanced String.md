# 1234. Replace the Substring for Balanced String

## 问题

给定只包含 `Q、W、E、R` 的字符串 `s`，长度 `n` 是 `4` 的倍数。若四种字符在**整个字符串中**都恰好出现 `n / 4` 次，就称为平衡字符串。可以选择**一段连续子串**，把它替换成任意同样长度的字符串，区间外的字符保持不变。求能让整个字符串平衡的**最短待替换子串长度**；原串已经平衡时返回 `0`。这里算的是所选区间的长度，不是实际发生变化的位置数，也不要求替换后的排列顺序固定。`4 <= n <= 10^5`。[题目链接](https://leetcode.com/problems/replace-the-substring-for-balanced-string/description/)

## 核心收获

### 不直接猜替换内容，先检查不能改变的部分

设目标数量 `target = n / 4`。窗口 `[left, right]` 是准备替换的部分，里面可以重新填写；窗口外的字符必须保留。因此：

```text
窗口可以通过替换使整串平衡
⇔ 窗口外 Q、W、E、R 的数量都 <= target
```

这个条件既必要，也充分：

- **必要**：如果外面已经有超过 `target` 个 `Q`，替换窗口内部也无法减少外面的 `Q`。
- **充分**：外部四种数量都不超标时，每种字符需要补 `target - outside[c]` 个，均为非负数。若窗口长度为 `len`，缺额总和为 `4 * target - (n - len) = len`，恰好填满窗口，所以一定能补成平衡字符串。

统计窗口外，是为了判断窗口能不能替换；**答案仍然是窗口本身的长度 `right - left + 1`**，不是外部长度。

### 用一个例子对齐窗口、计数和答案

`s = "QQQQWWER"`，长度为 `8`，所以每种字母最终都要有 `2` 个。让计数始终表示窗口外数量：

| 当前操作 | 待替换窗口 | 外部数量 `(Q,W,E,R)` | 是否可行 |
| --- | --- | --- | --- |
| 初始，尚未选择字符 | 空窗口 | `(4,2,1,1)` | 不可行，外部 Q 超标 |
| 纳入下标 `0` 的 Q | `[0,0]`：`Q` | `(3,2,1,1)` | 不可行 |
| 再纳入下标 `1` 的 Q | `[0,1]`：`QQ` | `(2,2,1,1)` | 可行，记下长度 `2` |
| 尝试缩小，移出下标 `0` | `[1,1]`：`Q` | `(3,2,1,1)` | 不可行，停止收缩 |

可行的 `QQ` 可以替换成 `ER`，得到 `ERQQWWER`。窗口外缺少一个 E、一个 R，正好对应两个可填位置。原串有两个多余的 Q，少于两个位置的区间无法替换掉它们，所以本例的最短长度为 `2`。

### 初始化为空窗口，计数从整个字符串开始

开始时先统计整串字符，`left = 0`，尚未选中任何位置。因此整个字符串都在窗口外。`right` 从 `0` 开始，是在枚举“逐步把哪些位置纳入待替换区间”，不是说长度为 `1` 的窗口一定可行。

两个移动方向对应的计数变化是：

```java
// s[right] 进入待替换窗口：它不再属于外部
outside[s.charAt(right)]--;

// s[left] 离开待替换窗口：它重新属于外部
outside[s.charAt(left)]++;
left++;
```

与统计窗口内部的题目相比，加减号正好相反；决定加减号的是“统计谁”，不是指针名字。

### 求最短：可行时先记录，再继续缩小

右端扩张会减少外部字符，可能让原本超标的数量降到目标内。一旦外部四种数量都不超标，当前窗口就能完成替换，此时执行：

```text
当窗口可行时，反复：
    用当前窗口长度更新最短答案
    把最左字符放回外部，left 前进
直到窗口不再可行，再继续扩张 right
```

必须先记录再收缩，因为缩小后的区间可能已经不满足条件。与 [[12-1208-Get Equal Substrings Within Budget]] 求最长合法窗口不同，本题是在**合法时尝试缩小答案**。

## 变种与注意点

- **原串已经平衡时直接返回 `0`**：此时空窗口就是答案。对于不额外检查左右边界的上述收缩写法，提前返回也避免了“空窗口仍然合法，左端继续越过右端”的问题。
- **也可以从右向左扫描**：只要对称地定义待替换区间，进入窗口仍从外部计数中减去，离开窗口仍加回。若改成从整串窗口开始，外部应初始化为空；不能只把 `right` 改到末尾，其余初始化和移动规则照搬。
- **`for` 里面有 `while` 不等于平方复杂度**：`right` 总共前进 `n` 次，`left` 也只会向前、总共至多前进 `n` 次，每次检查四种字符。因此时间为 `O(n)`，固定大小计数数组的额外空间为 `O(1)`。若先复制成字符数组，才会额外占用 `O(n)` 空间。
- **连续性会影响最短长度**：多余字符若分散在不同位置，为了把它们包含在同一段里，可能还必须选入中间的其他字符，不能只把四种字符的超额数量加起来当答案。

## 我的思维误区

### 把“统计外部”误当成“外部才是答案”

我曾混淆判断条件和优化目标。外部数量用于证明内部能否重新填写；真正可以操作的是选中的连续窗口，返回的也是它的最短长度。下次先分别写清“改哪里、统计哪里、返回什么”。

### 不理解为什么右端可以从 0 开始

我曾因为这里统计的是外部，困惑 `right` 为什么从 `0` 而不是字符串末尾开始。实际上 `right` 划定的是待替换窗口，`outside` 只记录剩余字符数量。初始窗口为空、外部是整串；第一轮纳入下标 `0` 后可能仍不可行，这时继续向右扩张即可。初始化要与窗口和计数的定义一致，不由变量名中的“外部”决定扫描方向。

### 按循环嵌套层数判断时间复杂度

我曾担心 `for + while` 会变成 `O(n²)`。这里内层不会为每个 `right` 重新从头扫描，`left` 从始至终只前进。应累计两个指针在整次运行中的移动次数，而不是直接把两个循环各算一次 `n` 相乘。
