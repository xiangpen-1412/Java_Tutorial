# 1658. Minimum Operations to Reduce X to Zero

## 问题

给定正整数数组 `nums` 和正整数 `x`。每次操作可以删除**当前数组最左端或最右端的一个元素**，并从 `x` 中减去该元素的值；删除后下一次操作面对的是剩余数组。求使 `x` **恰好变成 `0`** 的最少操作次数，如果无法做到则返回 `-1`。两边都可以删除，但不能直接取中间元素，超过目标也不算成功。题目范围为 `1 <= nums.length <= 10^5`、`1 <= nums[i] <= 10^4`、`1 <= x <= 10^9`。[题目链接](https://leetcode.com/problems/minimum-operations-to-reduce-x-to-zero/description/)

## 核心收获

### 两端删除 → 中间保留

不管左右两端的删除顺序如何，最终删除的都是一个前缀和一个后缀，剩下的是中间的一段连续子数组；某一边可以完全不删，中间也允许为空。

设数组总和为 `total`，删除部分的和需要恰好为 `x`，则：

```text
保留部分的和 = total - x = target
删除元素数   = n - 保留元素数
最少删除元素数 ⇔ 最长保留子数组
```

因此本题转化为：**找元素和恰好为 `target` 的最长连续子数组，最后返回 `n - maxLen`**。无需分别枚举每一种“从左边删几个、从右边删几个”的组合。

例如 `nums = [1,1,4,2,3]`、`x = 5`：总和为 `11`，要保留的和为 `6`。

| 中间保留的部分 | 保留的和 | 保留长度 | 对应删除次数 |
| --- | ---: | ---: | ---: |
| `[1,1,4]` | 6 | 3 | `5 - 3 = 2` |
| `[4,2]` | 6 | 2 | `5 - 2 = 3` |

两种保留方法都能让被删除部分的和为 `5`，但第一种保留得更长，删除次数更少。因此本例返回 `2`，不是保留长度 `3`。

### 正整数保证窗口和具有单调性

窗口向右加入元素，和只会增加；从左端移出元素，和只会减少。因此右端逐个加入元素后，如果 `sum > target`，就不断缩小左端，直到 `sum <= target`。

但“恢复到不超标”和“找到答案”是两件事：

```text
sum > target：必须收缩
sum < target：还不够，只能继续寻找，不能记录为答案
sum == target：删除部分的和才恰好是 x，可以更新最长保留长度
```

保留这段结构就能还原主要过程：

```java
sum += nums[right];
while (sum > target) {
    sum -= nums[left];
    left++;
}
if (sum == target) {
    maxLen = Math.max(maxLen, right - left + 1);
}
```

这里默认已经处理 `target <= 0` 的边界；`maxLen` 在寻找正目标时从 `-1` 开始，表示尚未找到任何满足等式的区间。

## 变种与注意点

- **`target < 0`**：`x` 大于整个数组的总和，删光都不够，直接返回 `-1`。
- **`target == 0`**：所有元素都是正数，保留和为 `0` 的部分只能是空数组，必须删除全部 `n` 个元素，返回 `n`。
- **`target > 0` 但最终没有相等的窗口**：返回 `-1`。应区分“没有找到答案”与“合法保留空数组”，不能不加判断地使用默认 `maxLen = 0`，否则会误报删除全部元素。
- **闭区间长度要加一**：窗口是 `[left, right]`，长度为 `right - left + 1`。这次代码里的少写 `+1` 是区间长度表达上的缺口，不应因此否定已经正确想到的两端删除转中间保留。
- **正数条件不可省略**：若允许负数，加入元素未必使和增大、移出元素也未必使和减小，这套按大小收缩的方法不再适用。可以改用前缀和与哈希表，寻找相差 `target` 的两个前缀，并保留最早出现的位置来获得最长区间。
- **复杂度看总移动次数**：两个指针都只向前，每个元素最多加入、移出各一次，时间为 `O(n)`，额外空间为 `O(1)`。本题总和最大为 `10^9`，`int` 足够；扩大输入范围后应重新检查是否需要 `long`。
- **区分等于与小于类题目**：本题是“和恰好等于目标的最长区间”；[[12-1208-Get Equal Substrings Within Budget]] 是“不超过预算的最长区间”，[[17-713-Subarray Product Less Than K]] 则是“乘积严格小于目标的区间数量”。外层形式相似，判断条件和答案更新方式仍由题目目标决定。

## 我的思维误区

### 已理解中间保留，但把 `<= target` 当作有效答案条件

我已经正确识别了“两端删除转中间保留”。问题出在把收缩结束的 `sum <= target` 直接当成记录答案的条件。如果 `sum < target`，删除部分的和就是 `total - sum > x`，会把 `x` 减成负数，不符合“恰好减到零”。下次把“什么时候停止收缩”和“什么时候满足题意”分别写出，本题必须在 `sum == target` 时更新答案。

### 计算的是保留长度，却忘记转换回删除次数

`maxLen` 是转换后的中间变量，题目要的是原问题中的操作次数。直接返回它就回答成了“最多能留下几个元素”。找到最长保留长度后，要回到最初等式 `删除数 = n - 保留数`；同时先判断是否确实找到过解。
