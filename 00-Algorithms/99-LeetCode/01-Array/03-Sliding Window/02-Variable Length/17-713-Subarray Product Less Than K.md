# 713. Subarray Product Less Than K

## 问题

给定正整数数组 `nums` 和整数 `k`，统计有多少个**连续、非空的子数组**，其所有元素的乘积**严格小于 `k`**，返回子数组的数量。这里的 `k` 是乘积上限，不是窗口长度；乘积等于 `k` 也不符合条件。子数组按原数组中的位置区间区分，可以重叠，数字也可以重复，例如 `[1,1]` 中两个不同位置的 `[1]` 分别计数。题目范围为 `1 <= nums.length <= 3 × 10^4`、`1 <= nums[i] <= 1000`、`0 <= k <= 10^6`。[题目链接](https://leetcode.com/problems/subarray-product-less-than-k/description/)

## 核心收获

### 从“找一个最优窗口”转为“按右端点统计所有合法窗口”

以前的题通常在窗口合法后，更新最大长度或最大总和。这题需要统计全部合法子数组，但不必把它们一个个生成出来。

先固定右端点 `right`，只统计**以这个位置结尾**的子数组。维护当前窗口 `[left, right]` 的乘积 `product`：加入右端元素后，如果 `product >= k`，就不断除掉 `nums[left]` 并让 `left` 前进，直到乘积重新小于 `k`。

这时 `left` 是以 `right` 结尾的最靠左合法起点。所有合法起点恰好是：

```text
left、left + 1、……、right

本轮新增数量 = right - left + 1
```

因此更新答案用的是：

```java
res += right - left + 1;
```

它是**一次加法**：利用规律直接算出本轮新增多少个子数组，不是在这行代码里又遍历了一遍整个窗口。

### 为什么这几个起点全部合法，且不会漏掉更左边的起点

关键条件是 **`nums[i] >= 1`**。

- **起点向右移动，乘积不会增大。** 如果 `[left, right]` 合法，去掉前面若干个至少为 `1` 的因子，得到的后缀也一定合法。因此从 `left` 到 `right` 的每个起点都能计数。
- **右端继续向右，乘积不会减小。** 如果某个更左边的起点已经因为乘积太大而被排除，再加入至少为 `1` 的因子，也不会让它重新合法。因此 `left` 不需要回退。

题目提示中的 `opt(j)` 就是在表达第二点：固定右端点 `j`，令 `opt(j)` 为最小的合法左端点，则它随 `j` 增大而**不下降**。这里不是严格递增；数组含有 `1` 时，乘积和左端点都可能保持不变。若当前没有合法的非空子数组，代码可用 `left = right + 1` 表示空窗口。

### 为什么按右端点计数不会重复

以 `nums = [10,5,2,6]`、`k = 100` 为例：

| `right` | 收缩后的最长合法窗口 | 本轮新增：只列以 `right` 结尾的子数组 | 新增数量 | 累计数量 |
| ---: | --- | --- | ---: | ---: |
| 0 | `[10]` | `[10]` | 1 | 1 |
| 1 | `[10,5]` | `[5]`、`[10,5]` | 2 | 3 |
| 2 | `[5,2]` | `[2]`、`[5,2]` | 2 | 5 |
| 3 | `[5,2,6]` | `[6]`、`[2,6]`、`[5,2,6]` | 3 | 8 |

到 `right = 2` 时，`[10,5,2]` 的乘积为 `100`，必须移出 `10`，因为题目要求严格小于 `100`。

最后一轮，窗口 `[5,2,6]` 内还有 `[5]`、`[2]`、`[5,2]` 等合法子数组，但它们的右端点在前面，已经计数，不能再加。每个子数组都有**唯一的右端点**，只在扫描到它结尾的那一轮计数，因此既不遗漏，也不重复。

### 状态持续保留，才真正避免重复工作

`left` 和 `product` 要放在右端点循环外，最初为 `0` 和 `1`。乘积从 `1` 开始，因为空窗口还没有加入因子；不能从 `0` 开始，否则后续怎么乘都还是 `0`。

每轮按同一顺序维护状态：

```text
乘入 nums[right]
→ 只要 product >= k，就除掉左端元素并右移 left
→ 窗口合法后，加上 right - left + 1
```

右指针总共前进 `n` 次，左指针也最多前进 `n` 次。虽然某一轮左指针可能连续走很多步，但之后不会从头重走这些位置，所以总时间是 **`O(n)`**，额外空间是 **`O(1)`**。

我的最初写法是固定每个 `left`，把 `right` 和 `product` 重置后重新向右试探。**按左端点分组计数本身没有错**，但这种重置会反复计算重叠区间。例如所有数字都为 `1`、`k = 2` 时，总共要扫描 `n + (n-1) + … + 1` 个位置，达到 `O(n²)`。效率的关键是复用边界和状态，而不是外层变量一定要叫 `right`。

## 变种与注意点

- **`k <= 1` 时直接返回 `0`。** 本题所有数字都是正整数，任何非空子数组乘积至少为 `1`。这也避免了空窗口的乘积恢复为 `1` 后，收缩条件仍然成立而继续越界。
- **单个数字超标时，本轮贡献为 `0`。** 当 `k > 1` 且 `nums[right] >= k`，收缩可能移出包括当前数字在内的全部窗口元素。此时 `left = right + 1`、`product = 1`，`right - left + 1` 正好等于 `0`。
- **判断乘积时注意计算范围。** 试探加入新元素时，可以让 `product` 使用 `long`，使乘法也按 `long` 运算。不要把整个数组的乘积一直累积下去；即使用 `long`，无限扩大的乘积也可能溢出。
- **这个计数公式有前提。** 它依赖“合法窗口的这些后缀全部合法”，不能把 `res += right - left + 1` 无条件套到所有子数组题。若允许负数，乘积符号可能改变；若允许 `0`，扩张时乘积可能突然变小，而且不能直接除以 `0`。原来的单调性和更新方式都需要重新分析。
- **普通前缀和记录的是加法。** `prefix[right + 1] - prefix[left]` 求的是区间总和，不能直接求本题的区间乘积。前缀积也可能很快溢出；这里利用相邻窗口“乘入、除出”来维护当前乘积即可。

## 我的思维误区

### 当前乘积合法，不代表下一项也能加入

我想固定 `left`，让 `right` 停在最远的合法位置，却写成先判断 `product < k`，再执行 `right++` 和乘法。这只确认了**旧窗口**合法，没有确认加入下一项后的新窗口是否合法。

例如 `nums = [80,1,2]`、`k = 100`、`left = 0`：`80` 可以加入，接着的 `1` 也可以加入，但再乘 `2` 会得到 `160`，应当停在下标 `1`。写边界前要明确 `right` 的含义：

| 区间定义 | `right` 表示什么 | 试探哪个位置 | 上例停止时 |
| --- | --- | --- | --- |
| 闭区间 `[left, right]` | 已加入的最后一个合法位置 | `right + 1` | `right = 1` |
| 半开区间 `[left, right)` | 下一次准备加入的位置 | `right` | `right = 2` |

两种定义都可以。半开写法以 `product = 1`、`right = left` 表示空窗口，每次先检查 `product * nums[right] < k`，再乘入并移动；闭区间写法则要检查下一位。不能沿用一种定义的初始化，却套用另一种定义的访问下标。

### 循环入口检查过边界，不代表移动后仍然安全

我曾写 `right < nums.length`，进入循环后先 `right++`，再访问 `nums[right]`。当旧 `right` 已是最后一个下标时，检查仍会通过，但移动后的访问已经越界。**边界判断必须保护实际要访问的下标**，不能只看循环开始时的指针是否有效。

### 以为统计全部子数组，就必须逐个扫描全部组合

我之前习惯用一个合法窗口更新最大值，没有分清“当前最长合法窗口”和“它代表的一组合法候选”。本题先按唯一右端点分组，再用连续的合法起点区间直接计数，才能把可能有 `O(n²)` 个的子数组压缩成 `n` 次加法。子数组数量很多，不代表为了得到数量就必须把它们全部列出来。
