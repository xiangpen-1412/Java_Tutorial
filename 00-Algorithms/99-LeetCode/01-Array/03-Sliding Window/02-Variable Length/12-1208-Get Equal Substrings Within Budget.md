# 1208. Get Equal Substrings Within Budget

## 问题

给定两个等长的小写字母字符串 `s`、`t` 和非负预算 `maxCost`，选择一个**连续下标区间**，把 `s` 在这个区间内的字符改成 `t` 在**相同下标区间**内的字符。每个位置的费用为 `|s[i] - t[i]|`，整段费用相加，要求不超过预算。返回满足条件的最大区间长度；如果没有符合条件的非空区间，返回 `0`。不需要转换整个字符串，也不能去 `t` 的其他位置寻找匹配片段。[题目链接](https://leetcode.com/problems/get-equal-substrings-within-budget/description/)

## 核心收获

### 字符转换 → 非负费用数组上的最长区间

每个位置都能独立转换成费用：

```java
cost[i] = Math.abs(s.charAt(i) - t.charAt(i));
```

`t[i]` 不保证比 `s[i]` 大。`a → b` 和 `b → a` 都花费 `1`；相同字符花费 `0`。绝对值使所有费用非负，不会出现一个位置的负费用抵消另一个位置的正费用。

因此问题变成：**寻找费用和不超过 `maxCost` 的最长连续区间**。例如：

```text
s       = "abcd"
t       = "bcdf"
cost    = [1, 1, 1, 2]
maxCost = 3
```

区间 `[0, 2]` 的费用为 `3`、长度为 `3`。加入下标 `3` 后，总费用变成 `5`；先移出下标 `0`，费用仍为 `4`，还需要再移出下标 `1`，才恢复为费用 `3` 的区间 `[2, 3]`。这说明一次加入后，左端可能需要连续收缩多次。

### 先加入，再恢复合法，最后记录长度

最容易统一状态的顺序是：

```text
加入 right 的费用，sum 对应闭区间 [left, right]
只要 sum > maxCost，就减去左端费用并让 left 前进
恢复合法后，用 right - left + 1 更新最大长度
```

此结构中 `sum` 从 `0` 开始，因为第一次循环立即加入下标 `0`。若某一个位置的费用就超过预算，收缩后可以出现 `left = right + 1` 的空区间，其长度为 `0`。

**非负费用是能够单向收缩的依据**：向右扩张不会降低总费用，移出左端不会增加总费用。一个左端点在当前右端下已经超预算，那么继续向右扩张也不会使它恢复合法，因此可以排除这个左端点，不用以后再试一次。

### 外层 `for` 与内层 `while` 表达不同的移动规律

右端每轮固定前进一步，用 `for` 能集中写清起点、边界和更新；左端可能移动零次或多次，用 `while` 表达“只要还超预算，就继续收缩”。外层换成正确的 `while`，算法和复杂度不会改变。

左右指针都只前进、不回头，每个位置最多加入一次、移出一次，合计 **`O(n)` 时间**。不是每个 `right` 都重新从头尝试所有 `left`。

## 变种与注意点

- **预算为 `0` 不等于答案必为 `0`**：原本相同的位置费用为零，连续的零费用位置可以保留，并计入长度。
- **不必真正建立费用数组**：预先创建 `char[]` 或 `cost[]` 需要 `O(n)` 额外空间；在左右端移动时直接用 `charAt()` 计算费用，可以做到 `O(1)` 额外空间。两种写法的窗口思路相同。
- **区间和条件遇到负数要重新分析**：若变种允许负费用，超预算的区间可能因后续加入负数而恢复合法，此时直接排除左端点的依据不再成立。
- **边界和类型由题目范围确定**：小写字母的单点费用至多为 `25`，长度至多为 `10^5`，总费用至多为 `2,500,000`，用 `int` 足够。

## 我的思维误区

### 认为循环入口的边界检查能保护本轮更新后的下标

原代码在本轮末尾先 `right++`，紧接着访问 `cost[right]`。当原来的 `right` 已经是最后一个下标时，自增后就越界；外层 `while (right < cost.length)` 要到下一轮才检查，来不及保护这次访问。

保留这种顺序时，必须在自增后、访问前再次检查边界。另一种更清楚的组织方式，是在本轮开头加入当前 `right`，让外层循环统一负责下一次移动。关键是检查**访问发生时**的下标，而不是只看循环入口有没有条件。

### 把初始 `sum` 改成零，却没有同时改变加入顺序

原结构以 `[0, 0]` 为初始窗口，因此从 `sum = cost[0]` 开始。如果只把它改成 `sum = 0`，仍然在循环末尾先 `right++` 再加入费用，第一次加入的就变成 `cost[1]`，下标 `0` 被漏掉了。

例如费用为 `[2, 2, 2, 2]`、预算为 `3` 时，窗口 `[0, 1]` 实际费用为 `4`，漏算下标 `0` 却会得到 `2`，把不合法的长度 `2` 当成可行。初始化、指针移动与求和顺序必须共同维护“`sum` 对应哪个区间”，不能独立替换其中一行。

### 判断长度公式前，先确定记录的是哪一段

我原来的结构在发现当前闭区间 `[left, right]` 超预算时，执行 `res = Math.max(res, right - left)`。这里记录的是**加入当前右端之前**的合法区间 `[left, right - 1]`，也可写成半开区间 `[left, right)`，所以不能直接断言少了 `+1`。

原结构在循环结束后，`right` 已经等于数组长度，最后用 `right - left` 补记 `[left, right)` 也有对应的含义。若改为“加入 → 收缩 → 记录当前合法闭区间”，长度才统一为 `right - left + 1`。复盘下标问题时，应先标明变量在当前阶段代表闭区间、半开区间，还是下一次待加入的位置。
