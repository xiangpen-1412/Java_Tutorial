# 424. Longest Repeating Character Replacement

## 问题

给定只包含大写英文字母的字符串 `s` 和整数 `k`，最多可以修改 `k` 个位置，每次把该位置的字符改成任意其他大写字母。求修改后能得到的**最长连续相同字母片段的长度**。不要求整条字符串都相同，也不要求用完修改次数；一次操作只影响一个位置。

例如 `AABABBA`、`k = 1`，把开头片段 `AABA` 中的 `B` 改成 `A`，可以得到长度为 `4` 的连续相同片段。`ABAB` 这种交替重复本身不符合“所有字母相同”。与 [[12-1208-Get Equal Substrings Within Budget]] 不同，这里 `A → B` 和 `A → Z` 都只算一次修改，不计算字符编码距离。

## 核心收获

### 先固定一段，推导最少需要修改多少个字符

窗口最终只能留下同一种字母。保留出现最多的字母，修改其他位置，需要的修改次数最少：

```text
最少修改次数 = 窗口长度 - 当前窗口内最高字母频次
可以修改成功 ⇔ 窗口长度 - 最高频次 <= k
```

例如 `AAABACAAA` 长度为 `9`，其中 `A` 有 `7` 个、`B` 和 `C` 各一个。保留七个 `A`，改掉另外两个位置，只需要 `9 - 7 = 2` 次。目标字母由当前窗口决定，不必预先固定，也不必真的生成修改后的字符串。

### 基础版本：维护当前窗口的真实频次

用 `int[26]` 表示 `A～Z` 的次数，下标可以写成 `c - 'A'`。右边加入字符时加一，左边移出时减一；扫描这 26 个计数，得到当前窗口的真实最高频次。

加入右端后，如果最少修改次数超过 `k`，持续移出左端；每次移出后，要重新计算当前最高频次和修改次数。恢复合法后，才用窗口长度更新最长结果。

缩短窗口不会增加最少修改次数：长度减一时，最高频次要么不变，要么也减一，因此二者的差不会增大。扩大窗口则不能让原本超预算的片段突然合法，这使已经排除的左端点不必回头。

**用数组替代 HashMap，并没有自动消除寻找最大值的遍历。** 本次指出“它们都是计数后找最大值”是正确的判断。字母只有 26 种，两种容器最多都只需检查 26 项，基础版本是 `O(26n) = O(n)`；这与每轮重新扫描整个窗口不同。

### 进一步减少扫描：最高频次只增不减

右端加入一个字符时，只有这个字符的次数可能刷新记录，所以可以只做一次比较：

```java
maxCount = Math.max(maxCount, frequencyOfNewChar);
```

如果收缩时不再重新计算或降低 `maxCount`，它的含义就变了：

| 状态 | 含义 |
| --- | --- |
| 字母计数数组 | 当前窗口的真实次数，移入移出都要更新 |
| `maxCount` | 扫描过程中记录过的最高单字母频次，只增不减 |

**历史版本中，`窗口长度 - maxCount <= k` 不再精确表示当前窗口真实合法。** 不能沿用基础版本的“收缩后窗口一定能改成功”来解释它。

以 `AABABBA`、`k = 1` 为例：

| 处理到的位置 | 处理后的窗口 | 当前真实最高频次 | 保存的 `maxCount` | 已找到的最大长度 |
| ---: | --- | ---: | ---: | ---: |
| 3 | `AABA` | 3 | 3 | 4 |
| 4 | `ABAB` | 2 | 3 | 4 |
| 5 | `BABB` | 3 | 3 | 4 |
| 6 | `ABBA` | 2 | 3 | 4 |

`ABAB` 实际需要改两次，但长度 `4` 已经由此前的合法片段 `AABA` 实现。保留这个长度并没有创造一个更大的错误答案。

### 历史值为什么不会让答案虚增

`maxCount` 因移出字符而过时，只会发生在收缩之后。触发收缩时，加入新字符使长度超过 `maxCount + k`；缩回后，长度回到这个上限。这个上限已经由此前的合法窗口实现过。

只要 `maxCount` 不变，后面每多加入一个字符，就需要移出一个，窗口长度不能超过这个已有上限。要产生更长的答案，必须有某种字母在当前窗口里的真实次数刷新 `maxCount`；此时新的更长窗口又有真实的合法依据。

历史值不小于当前真实最高频次，判断只会变宽松，不会把一个真实合法窗口过早排除；而过时状态又不能虚增答案。这两点分别保证不漏掉更优长度、不把不可实现的长度算作答案。

## 变种与注意点

- **先区分两种状态定义**：基础版每次扫描 26 项，保存当前真实最高频次；优化版保存历史最高频次。它们的解释不能混用，不能一边说“当前真实最大值”，一边在移出后不更新它。
- **返回内容改变时要重新分析**：历史版本适合这里求最大长度，最终维护的窗口未必是合法方案，不能直接把它作为替换片段返回；也不能据此统计全部合法窗口。
- **复杂度与空间分开判断**：两种写法时间都为 `O(n)`，优化版减少的是重复扫描的常数开销。计数数组只占固定空间；若另外调用 `toCharArray()`，完整实现仍会多出 `O(n)` 的字符副本。直接 `charAt()` 可保留 `O(1)` 额外空间。
- **`k = 0`**：只能选择原本已经连续相同的片段；`k` 足够大时，整个字符串可能都能被统一。

## 我的思维误区

### 只更新原始状态，没有更新由它算出的条件

原代码在进入收缩循环前只计算一次 `diff`，循环里只减少频次、移动 `left`，没有重算 `diff`。一旦 `diff > k`，条件就一直使用旧值，无法随着窗口缩短而结束，最终会越界。

要把状态分成两层：字符次数和边界是原始状态；最高频次、窗口长度、`diff` 是由它们推导的状态。原始状态改变后，下一次判断必须使用与新窗口一致的派生值。采用真实频次版本时，重新扫描前要把最大值变量清零，才能允许它下降。

### 对计数容器的选择与对最大值的维护，是两件事

本轮起初卡在“除 HashMap 统计后遍历，怎样知道其他字母有多少个”。先用“长度减去最高频次”把目标说明白，再决定如何维护频次。换成数组只让小字母表的实现更直接；避免每轮找最大值，需要另行解释历史记录为什么足够，不能把容器更换当成算法优化的证明。
