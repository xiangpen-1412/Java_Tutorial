# 1695. Maximum Erasure Value

## 问题

给定正整数数组 `nums`，选择并删除**恰好一段连续、非空、内部数字互不相同的子数组**，获得的分数等于被删除元素的总和。返回能够得到的最大分数；剩下的数组不影响得分。不能先删去重复数字，再把不连续的位置拼成候选。题目范围为 `1 <= nums.length <= 10^5`、`1 <= nums[i] <= 10^4`。[题目链接](https://leetcode.com/problems/maximum-erasure-value/description/)

## 核心收获

### 连续 + 不重复 + 正整数 → 维护无重复窗口的最大和

我的计数数组方案本身正确：先加入右端数字，再收缩左端直到重复消失，最后用窗口总和更新答案。

加入前，当前窗口已经没有重复，所以**新出现的冲突只可能由本次加入的 `nums[right]` 引起**。其他数字的次数没有增加，不需要每一轮扫描整个频次数组来判断是否重复：

```text
加入 nums[right]，同步增加它的频次与窗口总和
只要 freq[nums[right]] > 1，就从左端逐个移出
恢复无重复后，用当前窗口总和更新最大分数
```

窗口允许变化长度。与 [[11-2461-Maximum Sum of Distinct Subarrays With Length K]] 的区别在于，2461 还要求长度恰好为 `k`；本题满足连续和无重复即可。

### 频次数组与总和必须描述同一个窗口

例如 `nums = [4, 2, 4, 5, 6]`：

| 新加入的数字 | 收缩操作 | 恢复合法后的窗口 | 窗口和 |
| --- | --- | --- | ---: |
| 第一个 `4` | 不需要 | `[4]` | 4 |
| `2` | 不需要 | `[4, 2]` | 6 |
| 第二个 `4` | 从左端移出第一个 `4` | `[2, 4]` | 6 |
| `5` | 不需要 | `[2, 4, 5]` | 11 |
| `6` | 不需要 | `[2, 4, 5, 6]` | 17 |

加入第二个 `4` 时，窗口和先变为 `10`，移出第一个 `4` 后变为 `6`。不能只修改频次，却忘记从总和中减去移出的值；两个状态都必须对应 `[left, right]`。

重复值不一定在窗口最左端，因此要使用 `while`。如果旧的同值元素前面还挡着其他数字，也必须依次移出它们，直到旧的同值元素离开；不能跳过中间位置，否则不再是连续子数组。

### 为什么只保留当前右端下最长的无重复窗口

消除冲突后，当前窗口的左端尽可能靠前。任何更早的左端都会包含重复值，任何更晚的左端则会丢掉一些元素。由于**数组全部为正整数**，丢掉元素只会使总和减小，所以固定右端时，最长的合法窗口也是总和最大的合法窗口。

这才是无需枚举当前右端下所有合法左端点的原因。左右指针都只前进，每个元素最多加入一次、移出一次，因此总时间为 **`O(n)`**。

## 变种与注意点

- **计数数组可以按值域缩小**：我原来使用 `int[100000]`，题目数字最大为 `10000`，改成 `int[10001]` 已经足够；数组需要包含下标 `10000`。额外空间为 `O(U)`，`U` 是值域大小，在本题固定上限下可视为 `O(1)`。若值域很大或含负数，可用集合或映射记录窗口状态。
- **只记录是否存在时，要先排重再加入**：可以改用 `boolean[] seen`，但布尔值不能区分“出现一次”和“出现两次”。因此必须在新数字加入之前，持续移出左端直到 `seen[nums[right]]` 为假，再把当前数字标为存在并加入总和。直接沿用计数版本的“先加入再判断次数”顺序，会丢失区分新旧同值元素的信息。
- **更换容器没有改变算法**：频次数组、布尔数组或集合都可以维护无重复窗口，差别在状态含义、操作顺序和实际开销；它们不会让已经线性的遍历变成更低的时间复杂度。
- **允许负数时不能照搬最大和结论**：固定右端时，更长的合法窗口可能因包含负数而总和更小。无重复的维护仍能使用，但“只看最长合法窗口就能得到最大和”的依据需要替换。
- **本题的和用 `int` 足够**：即使按整个数组估计，总和也至多为 `10^9`；扩大值域或数组长度的变种需要重新检查是否使用 `long`。
