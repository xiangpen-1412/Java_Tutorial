# 992. Subarrays with K Different Integers

## 问题

给定正整数数组 `nums` 和正整数 `k`，统计有多少个连续、非空子数组，包含**恰好 `k` 种不同的整数**。同一个整数出现多次仍然只算一种；例如 `[1,2,1,2]` 有四个元素，但只有 `1`、`2` 两种数。子数组按起止位置分别计数，即使内容相同，也可能是不同的答案。[题目链接](https://leetcode.com/problems/subarrays-with-k-different-integers/description/)

本轮对话主要记录题意理解，以及从 930、1248 迁移“恰好转至多”的思路，没有展示并核验独立完整实现。完成进度按用户确认记入 menu，本文不据此声称已经独立熟练，也不把缺少代码记录当成未完成。

## 核心收获

### 从“次数”迁移到“种类数”

[[20-930-Binary Subarrays With Sum]] 维护窗口和，[[21-1248-Count Number of Nice Subarrays]] 维护奇数数量；本题维护窗口里不同整数的种类数 `distinct`。

种类数也是非负整数，所以同样有：

```text
恰好 k 种的子数组数量 = atMost(k) - atMost(k - 1)
```

其中 `atMost(limit)` 统计至多含 `limit` 种整数的子数组。两个统计集合相减后，少于 `k` 种的区间被抵消，只留下恰好 `k` 种的区间。

### 需要频次数组或映射，才能正确维护种类数

不同于奇偶性可以逐个元素独立加减，移入、移出一个数是否改变种类数，取决于**窗口中还有没有其他相同的数**。

| 操作 | 频次变化 | `distinct` 是否变化 |
| --- | --- | --- |
| 加入一个数 | 从 `0` 变成 `1` | 增加 `1` |
| 加入一个数 | 原来已经大于 `0` | 不变 |
| 移出一个数 | 减少后仍大于 `0` | 不变 |
| 移出一个数 | 从 `1` 变成 `0` | 减少 `1` |

如果用映射的 `size()` 表示种类数，频次降到 `0` 时要删除对应键；如果单独维护 `distinct`，则必须在频次变为 `0` 的那一步才减少种类数。

每次加入右端元素后，只要 `distinct > limit`，就移出左端元素，直到 `distinct <= limit`。然后本轮增加 `right - left + 1`。

### 为什么这里仍能按窗口长度计数

从一个窗口中删除元素，不同整数的种类数不会增加。因此至多含 `limit` 种数的窗口，其所有后缀也都合法；固定 `right`，合法起点为 `left` 到 `right`。

向右加入元素，种类数也不会减少，所以之前因种类过多而排除的更左起点不会重新合法，左指针仍然无需回退。沿用的是这两个单调性质，而不是把“窗口和”公式直接照搬过来。

### 例子：`[1,2,1,2,3]`，`k = 2`

按右端点列出恰好含两种数的区间：

| `right` | 合法起点 | 对应子数组 | 数量 |
| ---: | --- | --- | ---: |
| 0 | 无 | 无 | 0 |
| 1 | `0` | `[1,2]` | 1 |
| 2 | `0、1` | `[1,2,1]`、`[2,1]` | 2 |
| 3 | `0、1、2` | `[1,2,1,2]`、`[2,1,2]`、`[1,2]` | 3 |
| 4 | `3` | `[2,3]` | 1 |

答案是 `0 + 1 + 2 + 3 + 1 = 7`。用至多计数也能得到 `atMost(2) = 12`、`atMost(1) = 5`，差为 `7`。

在 `atMost(2)` 的最后一轮，加入 `3` 后频次为 `{1:2, 2:2, 3:1}`，有三种数。依次移出开头的 `1`、`2` 时，它们的频次都只是从 `2` 降到 `1`，种类数仍是 `3`；继续移出下一个 `1`，其频次才降到 `0`，种类数降为 `2`，窗口成为 `[2,3]`。这说明收缩必须用循环，也说明不能每移走一个元素就让 `distinct--`。

## 变种与注意点

- **重复值不等于新增种类。** `[1,1,1]` 始终只有一种数；同一数在窗口内出现多少次，需要由频次状态保存。
- **`atMost(0) = 0`，但理由与 930、1248 不同。** 本题任何非空窗口至少有一种整数，所以没有至多零种的非空区间。930 的全零窗口、1248 的全偶窗口则可以合法贡献给各自的 `atMost(0)`。通用实现也可以对负上限直接返回 `0`。
- **本题不要求元素的大小具有单调性。** 窗口维护的是种类数，数值本身的正负、大小不影响“加入不会减少种类、删除不会增加种类”。如果推广到任意整数，可用映射维护频次。
- **复杂度取决于频次结构。** 使用映射时，平均每次更新为 `O(1)`，两趟扫描总时间为 `O(n)`；额外空间取决于需要保存的不同值数量，最坏为 `O(n)`。若值域较小，也可用频次数组。
- **迁移时先换清楚状态，再复用计数结构。** 外层仍是“加入右端 → 超标就收缩 → 加合法起点数”，但本题的关键状态变化是频次在 `0` 与 `1` 之间切换时才改变种类数。
