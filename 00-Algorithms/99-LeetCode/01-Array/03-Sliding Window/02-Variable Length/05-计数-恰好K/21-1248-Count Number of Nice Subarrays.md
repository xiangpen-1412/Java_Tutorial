# 1248. Count Number of Nice Subarrays

## 问题

给定整数数组 `nums` 和正整数 `k`，统计包含**恰好 `k` 个奇数**的连续、非空子数组数量，这样的子数组称为 nice subarray。偶数可以出现在开头、中间或结尾，不影响奇数数量，但会影响子数组的起止位置，因此可能增加答案。这里关心的是奇数的个数，不是元素总和，也不是子数组长度。[题目链接](https://leetcode.com/problems/count-number-of-nice-subarrays/description/)

## 核心收获

### 奇数看成 1，偶数看成 0

本题与 [[20-930-Binary Subarrays With Sum]] 的对应关系是：

```text
奇数 → 1
偶数 → 0
子数组中奇数的个数 → 转换后子数组的和
恰好 k 个奇数 → 转换后的和恰好为 k
```

不必实际创建转换后的数组，只要右端加入奇数时让 `times++`，左端移出奇数时让 `times--`。偶数也占据窗口中的一个位置，因此指针要照常移动，但 `times` 不变。

### `cal(limit)` 统计“至多”，不是直接统计“恰好”

本轮已经写出了正确的 `cal` 思路：让它返回奇数个数**不超过 `limit`** 的子数组数量，最终用 `cal(k) - cal(k - 1)` 得到答案。

```text
至多 k 个奇数：   0 个、1 个、……、k 个
至多 k-1 个奇数： 0 个、1 个、……、k-1 个
相减：只留下恰好 k 个奇数的区间
```

每轮右端加入元素后，`while (times > limit)` 负责移出左端元素。循环结束只保证 **`times <= limit`**，不要求一定等于 `limit`。这正是 `cal` 的目标；奇数不足上限的窗口也应该统计，之后通过相减去掉它们。

### 为什么 `res += right - left + 1` 正好统计本轮贡献

当 `[left, right]` 至多含 `limit` 个奇数时，删除它前面的一些元素不会增加奇数数量。因此，固定 `right`，从 `left` 到 `right` 的所有位置都可以作为合法起点，共 `right - left + 1` 个。

例如窗口 `[2,1,2]`、`limit = 1`，以最后一个 `2` 结尾的合法子数组是：

```text
[2,1,2]：1 个奇数
  [1,2]：1 个奇数
    [2]：0 个奇数
```

本轮应增加 `3`，其中最后一个区间虽然没有奇数，仍然满足“至多一个”。这里的窗口长度是在数**固定右端点时的合法起点数**，不是说窗口里所有子数组都只有这三个；右端点更早的子数组已经在前面计过。

### 例子：两边的偶数增加起止位置选择

`nums = [2,1,2,1,2]`、`k = 2`，可看成二元数组 `[0,1,0,1,0]`。

两个奇数在下标 `1` 和 `3`。要同时包含它们，起点可以选 `0` 或 `1`，终点可以选 `3` 或 `4`，共四个合法区间：

| 下标区间 | 子数组 |
| --- | --- |
| `[0,3]` | `[2,1,2,1]` |
| `[1,3]` | `[1,2,1]` |
| `[0,4]` | `[2,1,2,1,2]` |
| `[1,4]` | `[1,2,1,2]` |

用本轮窗口方法，`cal(2) = 15`，`cal(1) = 11`，因此答案也是 `15 - 11 = 4`。

## 变种与注意点

- **`times` 是窗口中的奇数数量，不是窗口长度。** 一个很长的窗口也可能只有少量奇数；收缩时移走偶数不能减少 `times`，否则状态就与实际窗口不一致。
- **`limit = 0` 有正常含义。** 它统计全由偶数组成的子数组，不能直接返回 `0`。题目 `k >= 1`，但 `k = 1` 时必须计算 `cal(0)`。
- **若把 `cal` 写成通用函数，`limit < 0` 返回 `0`。** 奇数数量不会是负数；这也支持“恰好零个奇数”的扩展问题。
- **收缩可以留下空窗口。** 当 `limit = 0` 且新加入的是奇数，会一直移出到该奇数也被删除。此时 `left = right + 1`，本轮 `right - left + 1 = 0`，不计空子数组。
- **可以换成其他逐元素判断。** 例如“恰好 `k` 个负数”“恰好 `k` 个大于某阈值的数”，只需把符合条件的元素记为 `1`、其余记为 `0`。原始元素本身可能为负数也不影响这种转换，因为窗口维护的是非负的条件计数，不是原始总和。
- **复杂度由指针总移动次数决定。** 每个元素在一趟 `cal` 中最多加入、移出各一次；两趟合计时间 `O(n)`，额外空间 `O(1)`。

本轮的重点是确认已经写对的 `cal` 为什么成立：`while` 负责恢复“至多”的条件，窗口长度负责统计当前右端点的全部合法起点，最后相减才回到题目要求的“恰好”。
