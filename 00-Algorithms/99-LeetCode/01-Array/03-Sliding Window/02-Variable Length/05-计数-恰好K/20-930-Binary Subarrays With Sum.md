# 930. Binary Subarrays With Sum

## 问题

给定只包含 `0` 和 `1` 的数组 `nums` 和整数 `goal`，统计有多少个**连续、非空的子数组**，其元素和**恰好等于 `goal`**。由于元素只有 `0` 和 `1`，也就是统计恰好包含 `goal` 个 `1` 的子数组。子数组按位置区分，内容相同但起止下标不同，也要分别计数；`goal = 0` 时，统计的是全由 `0` 组成的非空区间。[题目链接](https://leetcode.com/problems/binary-subarrays-with-sum/description/)

## 核心收获

### “恰好”不便直接计数，转成两个“至多”之差

定义 `atMost(limit)` 为元素和**不超过 `limit`** 的非空子数组数量。由于区间和是整数：

```text
atMost(goal)     包含：和为 0、1、……、goal 的子数组
atMost(goal - 1) 包含：和为 0、1、……、goal - 1 的子数组

恰好等于 goal 的数量 = atMost(goal) - atMost(goal - 1)
```

这是对两组子数组做减法：第二组完全包含在第一组里，减去所有和偏小的区间，剩下的恰好就是目标区间。不是把两个窗口的元素和相减，也不需要找出两次扫描中哪个具体窗口对应哪个窗口。

### 为什么“至多”可以一次统计一组起点

维护闭区间 `[left, right]` 及窗口和 `sum`。每次加入 `nums[right]`，只要 `sum > limit` 就移出左端，直到 `sum <= limit`。

非负条件提供了两个性质：

- **从左端删除元素，和不会增加。** 当前 `[left, right]` 合法后，从 `left` 到 `right` 的每个位置都能作为合法起点；对应窗口都是当前窗口的后缀。
- **向右加入元素，和不会减少。** 之前因为和过大而排除的更左起点，不会在右端继续延伸后重新合法，所以左指针无需回退。

因此固定当前右端点，合法起点恰好是 `left、left + 1、……、right`，本轮新增数量为 `right - left + 1`。

```java
sum += nums[right];
while (sum > limit) {
    sum -= nums[left++];
}
res += right - left + 1;
```

这段结构用于 `atMost`，前提是已处理 `limit < 0`。它统计的只是**以当前 `right` 结尾**的子数组，不是把窗口内部所有子数组重新数一遍。每个子数组有唯一的右端点，因此不会重复。

### 一个例子同时看懂两趟统计

`nums = [1,0,1,0,1]`、`goal = 2`：

| `right` | `atMost(2)` 本轮新增 | `atMost(1)` 本轮新增 | 两者之差：本轮和恰好为 2 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 1 | 0 |
| 1 | 2 | 2 | 0 |
| 2 | 3 | 2 | 1 |
| 3 | 4 | 3 | 1 |
| 4 | 4 | 2 | 2 |
| 合计 | 14 | 10 | **4** |

最后一轮，`atMost(2)` 的合法起点为 `1、2、3、4`，`atMost(1)` 的合法起点为 `3、4`。相减后保留起点 `1、2`，分别对应 `[0,1,0,1]` 和 `[1,0,1]`，所以这轮新增两个答案。

全部四个合法区间是 `[0,2]`、`[0,3]`、`[1,4]`、`[2,4]`，这里写的是包含两端的下标区间。

## 变种与注意点

- **`limit < 0` 直接返回 `0`。** 非负数组没有和小于 `0` 的非空子数组。`goal = 0` 时会计算 `atMost(-1)`，必须在进入窗口循环前处理；否则空窗口的和已经是 `0`，仍然大于负上限，会继续错误收缩。
- **空窗口自然贡献 `0`。** 例如 `[1]`、`limit = 0`，移出这个 `1` 后 `left = right + 1`，`right - left + 1 = 0`，不会把空数组计入。`[0,0]`、`goal = 0` 则贡献 `1 + 2 = 3`，三个区间分别是两个单独的 `0` 和整个数组。
- **两趟扫描仍是 `O(n)`。** 每趟中左右指针都最多移动 `n` 次，总时间 `O(n)`，额外空间 `O(1)`。本题的二元数组允许维护一个和；遇到负数时，上述窗口单调性不再成立。
- **同一转换可迁移到其他整数指标。** [[21-1248-Count Number of Nice Subarrays]] 把元素换成“是否为奇数”；[[22-992-Subarrays with K Different Integers]] 把窗口指标换成“不同整数的种类数”，但需要额外维护频次。

### 前缀和是另一条路线，主线仍是窗口

若 `prefix[i]` 表示前 `i` 个元素之和，则 `[left, right]` 的和为 `prefix[right + 1] - prefix[left]`。当前前缀和为 `curr` 时，要找之前出现过多少次 `curr - goal`：每个匹配的前缀位置都给出一个合法起点。

在线统计需要初始 `freq[0] = 1`，表示没有读取元素时的空前缀；每步**先查询旧频次，再登记当前前缀**，否则 `goal = 0` 时会把当前前缀与自身配对，误计空子数组。

本轮还讨论了“先统计全部前缀和频次，再相乘”的离线思路。对于本题的非负数组，前缀和非递减，因此：

```text
goal > 0：答案 = Σ freq[s] × freq[s - goal]
goal = 0：答案 = Σ freq[s] × (freq[s] - 1) / 2
```

正目标时，较小的前缀和一定出现在较大的前缀和之前，每个配对都满足下标顺序。零目标时则从相同前缀和的位置中选两个不同位置，不能直接取频次的平方。完整频次必须包含初始空前缀 `0`；`s == goal` 时也不能只加 `freq[goal]`，因为开头的零可能让 `freq[0] > 1`。例如 `[0,1]` 的前缀为 `[0,0,1]`，`goal = 1` 时要算 `1 × 2 = 2`。

若数组允许负数，较小的前缀和不保证在前面，正目标的这种离线相乘会丢失顺序信息；在线查询“之前”的前缀频次仍可使用。

## 我的思维误区

### `sum == goal` 就立即缩左端，会丢掉以后仍然有效的起点

我尝试在 `sum == goal` 时计数并收缩。问题是右边可能继续出现 `0`，原来的合法起点仍有新答案，但左指针已经移走了。

在上例中，`right = 2` 时 `[0,2]` 的和为 `2`。若计数后移出下标 `0` 的 `1`，就变成 `left = 1`、`sum = 1`。下一步 `right = 3` 加入 `0`，和仍为 `1`，于是漏掉了本来合法的 `[0,3]`。这里不是“滑动窗口不能做”，而是直接等于就收缩的计数方式没有保留全部贡献；改为统计两个“至多”，才能直接利用起点区间。

### 把相等判断放在收缩前，会漏掉收缩后才合法的窗口

我的另一版顺序是“加入右端 → 如果相等就 `res++` → 如果超标就收缩”。例如 `[1,1]`、`goal = 1`，第二个 `1` 加入时和为 `2`，相等判断不成立；移出第一个 `1` 后和恢复为 `1`，却没有再次判断，因此只得到 `1`，正确答案是 `2`。

把判断移到收缩后只能修复这个时机问题，不能解决所有漏计。并且 `goal = 0` 时，若收缩成空窗口后只看 `sum == goal`，还会误计空数组：`[1]` 收缩后和为 `0`，但没有合法的非空子数组。

### 每次相等只加一，忽略了同一个右端点可能对应多个起点

例如 `[0,1]`、`goal = 1`，最后一个位置结尾的 `[0,1]` 和 `[1]` 都合法，单次 `res++` 只能记录一个。`[0,0]`、`goal = 0` 同样应得到 `3`，每轮只加一却只能得到 `2`。

下次先明确“本轮代表多少个合法起点”，再决定加什么。`atMost` 收缩后的合法起点构成连续区间，所以加窗口长度；“恰好”的数量则通过两个至多计数相减得到，不能直接把合法窗口数量当成一。
